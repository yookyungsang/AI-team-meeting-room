## 설치 확인

이미 최신 버전을 설치하고 Codex를 다시 실행했다면 [다음 단계](#작업할-프로젝트-열기)로 이동합니다.

처음 설치할 때는 Node.js 22 이상, Git, 로컬 플러그인과 MCP Apps를 지원하는 Codex 및 `codex` 명령이 필요합니다. 터미널에서 다음 명령을 순서대로 실행합니다. Windows에서는 PowerShell을 사용할 수 있습니다.

```sh
git clone https://github.com/yookyungsang/AI-team-meeting-room.git
cd AI-team-meeting-room
codex plugin marketplace add .
codex plugin add jyfood-room@jyfood-local
```

설치 결과에 표시되는 플러그인 ID는 `jyfood-room@jyfood-local`, 표시 이름은 **팀 회의실**입니다. 마지막 명령은 위에서 내려받은 `AI-team-meeting-room` 폴더 안에서 실행합니다.

진행 중인 작업을 마친 뒤 **Codex를 완전히 종료하고 다시 실행**합니다. 설치 명령이 성공했어도 이미 열린 대화가 새 도구를 바로 읽는다고 보장하지는 않습니다.

**이 단계의 완료 기준:** 설치 명령이 오류 없이 끝나고, 재시작한 Codex에서 팀 회의실 플러그인을 사용할 수 있어야 합니다. 명령 자체를 찾지 못한다면 [문제 해결](#중단됐거나-잘-안-될-때)을 확인합니다.

## 작업할 프로젝트 열기

Codex에서 **실제로 만들거나 수정할 프로젝트 폴더**를 엽니다. 아직 Codex에 등록하지 않았다면 그 폴더를 프로젝트로 연 뒤, 그 프로젝트에 속한 일반 대화창 하나를 엽니다. 그 대화에서 팀 구성을 요청하면 됩니다.

플러그인을 내려받은 폴더는 설치용 소스입니다. 게임을 만들려면 게임 프로젝트를, 웹 앱을 만들려면 해당 웹 앱 프로젝트를 선택합니다. 팀 회의실 플러그인 자체를 개발할 때만 이 저장소를 작업 대상으로 선택합니다.

다음처럼 먼저 확인해도 됩니다.

```text
지금 열려 있는 프로젝트가 내가 작업할 프로젝트인지 확인해 줘.
아직 작업자나 회의실을 만들지는 말고, 확인한 프로젝트 이름부터 알려 줘.
```

프로젝트 이름이 맞으면 다음 단계로 넘어갑니다. 여러 프로젝트가 후보로 나오면 원하는 프로젝트를 지정합니다. **채팅 ID나 회의실 설정 파일을 직접 찾아 적을 필요는 없습니다.** 에이전트가 실제 프로젝트와 채팅 정보를 확인합니다.

## 새 작업자 여섯 명 만들기

앞에서 연 **프로젝트의 Codex 채팅 입력창**에 아래 내용을 복사해서 보냅니다. 회의실이 아직 없어도 사용할 수 있습니다.

```text
이 프로젝트에 팀 회의실을 세팅해 줘.
총괄 디렉터 1명, 기획자 1명, 디자이너 1명,
프로그래머 2명, QA 1명을 각각 별도 대화창으로 만들어 줘.
새 채팅 이름은 프로젝트와 역할을 알아보기 쉽게 붙여 줘.
역할별 이름, 새로 만들지 기존 채팅을 쓸지,
추천 모델과 추론 수준을 먼저 표로 보여 줘.
내가 모델을 선택하면 생성과 역할 지침 설정, 회의실 연결까지 진행해 줘.
이미 이 프로젝트에 연결된 담당자가 있다면 먼저 확인해서 유지해 줘.
이번에는 팀 구성까지만 하고 구현 작업은 시작하지 마.
```

Codex는 프로젝트와 현재 사용할 수 있는 대화창 생성 기능·모델 선택지를 확인하고 구성표를 준비합니다. 이 표는 **채팅 답변으로** 나옵니다. 별도의 ‘팀 생성’ 버튼이나 모델 선택 전용 화면을 찾을 필요는 없습니다.

| 역할 | 맡는 일 |
| --- | --- |
| 총괄 디렉터 | 전체 설계, 우선순위, 작업 배분, 충돌 조율, 통합과 완료 판단 |
| 기획자 | 시스템·밸런스·레벨 기획, 기능 사양과 완료 기준 |
| 디자이너 | UI·캐릭터·배경·3D 등 시각 결과의 기획과 제작 |
| 프로그래머 1 | 핵심 로직·데이터 구현을 우선 담당 |
| 프로그래머 2 | 화면·상호작용 구현을 우선 담당 |
| QA | 독립 검증, 오류 재현, 회귀 확인과 증거 정리 |

두 프로그래머의 실제 분담은 총괄이 작업에 맞춰 정합니다. 같은 파일을 동시에 수정하지 않도록 나누고, 구현 담당자의 자체 점검 뒤 QA가 검증합니다. 준비된 역할 중 실제 작업에 필요한 담당자만 참여합니다.

**이 단계의 완료 기준:** 여섯 역할이 구성표에 있고 프로그래머가 두 명인지, 대상 프로젝트와 새 채팅·기존 채팅 구분이 맞는지 확인합니다. 잘못된 부분은 생성 전에 같은 대화에서 수정합니다.

## 역할별 모델 선택

에이전트가 보여 준 **현재 지원 모델과 추론 수준**을 보고 선택합니다. 추천표는 자동 적용되지 않습니다. 모델 이름·추론 수준은 호스트와 계정에 따라 달라질 수 있으므로 이 문서에 고정된 목록을 입력할 필요는 없습니다.

### 방법 A · 기본 설정 유지

모델별로 정하고 싶지 않다면 다음처럼 답합니다.

```text
여섯 역할 중 새로 만드는 채팅은 모두 내 기본 모델과 기본 추론 설정을 유지해 줘.
방금 확인한 구성으로 대화창을 만들고 회의실에 연결해 줘.
```

여기서 기본 설정은 **Codex가 새 대화에 사용하는 사용자 기본값**입니다. 현재 열린 대화의 개별 모델 설정을 여섯 채팅으로 복사한다는 뜻은 아닙니다. 이미 연결된 기존 채팅은 그 채팅의 현재 설정을 유지합니다.

### 방법 B · 방금 제안한 추천표 선택

구체적인 모델 이름과 추론 수준이 적힌 추천표를 확인한 뒤 다음처럼 답합니다.

```text
방금 표에 보여 준 역할별 모델과 추론 수준을 그대로 선택할게.
그 설정으로 새 대화창 생성과 역할 지침 설정, 회의실 연결까지 진행해 줘.
```

### 방법 C · 역할별로 직접 지정

표에 나온 정확한 모델 이름과 추론 수준을 복사해 **역할별 선택을 문장이나 표로** 전달합니다. 프로그래머 1과 2를 각각 지정할 수 있습니다. 선택을 바꿀 때도 구체적으로 알려 줍니다. 지원되지 않는 설정은 임의의 다른 모델로 바꾸지 않고 확인이 필요합니다.

추론 수준은 모델이 판단에 쓰는 노력의 설정입니다. 높은 수준을 모든 업무에 고정하면 효율이 좋아진다고 보장할 수 없습니다. 기본 설정으로 시작하거나, 통합·복잡한 구현·검증 같은 역할의 실제 난이도를 보고 선택합니다. 추천은 선택을 돕는 안내이며 품질이나 사용량 절감률을 보장하지 않습니다.

**이 단계의 완료 기준:** 새로 생성할 역할들의 모델 선택이 정해지고, 에이전트가 해당 설정으로 생성을 진행해야 합니다. 모델 선택이 이미 구체적으로 끝났다면 같은 승인을 반복할 필요는 없습니다.

## 연결 완료 확인과 회의실 열기

선택을 마치면 Codex가 실제 새 대화창을 만들고, 제목과 역할 지침을 설정한 뒤 실제 채팅 정보로 회의실에 연결합니다. 예를 들어 이름은 `내 프로젝트 · 프로그래머 1`처럼 표시될 수 있습니다. 이는 설명용 이름 예시이며 실제 이름은 구성표에 따라 달라집니다.

에이전트가 안내한 새 채팅 링크나 Codex의 대화 목록에서 **이 프로젝트의 총괄 디렉터 채팅**을 엽니다. 어느 채팅인지 모르겠다면 구성을 진행한 대화에 이렇게 요청합니다.

```text
이 프로젝트의 회의실에 연결된 총괄 대화창이 어느 것인지 알려 줘.
그 대화창을 열어 줘.
```

그 총괄 채팅에서 다음을 보냅니다.

```text
이 프로젝트의 팀 회의실을 열어 줘.
```

| 확인할 위치 | 확인할 내용 |
| --- | --- |
| 회의실 상단 프로젝트 | 내가 작업할 프로젝트가 선택되어 있는지 |
| 상단 **메뉴 → 팀과 회의 제어** | 총괄·기획자·디자이너·프로그래머 2명·QA가 연결됐는지 |
| Codex 대화 목록 또는 새 채팅 링크 | 새로 만든 담당자가 실제 별도 대화창으로 있는지 |

기존 팀을 확장했다면 이전 담당자도 함께 보일 수 있습니다. 팀 생성 과정은 기존 총괄이나 추가 담당자를 자동으로 삭제하지 않습니다.

**이 단계의 완료 기준:** 실제 대화창과 회의실의 담당자 목록이 확인되고, 올바른 프로젝트의 회의실 입력창에서 요청을 보낼 수 있어야 합니다. 회의실 상단의 프로젝트 선택은 표시할 기록을 바꾸며, Codex의 현재 총괄 채팅 자체를 다른 채팅으로 이동시키지는 않습니다.

## 첫 작업 지시와 중간 수정

이제 **회의실 하단 입력창**에 작업을 보냅니다. `Enter`는 전송, `Shift+Enter`는 줄바꿈입니다. 다음은 첫 작업 요청의 예시입니다. 원하는 실제 기능으로 내용을 바꿉니다.

```text
설정 화면을 읽기 쉽게 개선해 줘.
기존 버튼 동작과 저장 데이터는 유지해 줘.
이 프로젝트에 연결된 담당자에게 필요한 작업을 배정하고,
담당자끼리 업무 질문과 결과를 주고받는 협업을 허용할게.
두 프로그래머는 필요한 경우 서로 다른 파일로 작업을 나눠 줘.
개발자 자체 점검 뒤 QA가 영향 범위를 검증해 줘.
중간 이미지는 판단이 필요할 때만 보여 주고,
완료된 화면은 만든 담당자가 최종 보고에 이미지로 첨부해 줘.
```

총괄은 필요한 담당자에게 작업을 나누고 결과를 통합합니다. 담당자는 자신의 의미 있는 질문·진행·결과를 회의실에 남깁니다. 첫 작업 지시에 협업 연락 범위를 함께 적으면 총괄이 실제 사용자 허용 범위를 확인하기 쉽습니다.

작업 도중 바꿀 조건이 생기면 **같은 회의실 입력창**에 추가로 보냅니다.

```text
방금 요청한 설정 화면은 휴대폰에서도 읽기 쉽게 해 줘.
버튼 위치는 유지하고 글자 크기와 간격을 먼저 조정해 줘.
```

추가 내용은 가장 최근의 진행 중인 원래 요청에 연결되고, 총괄이 반영한 뒤 완료하도록 되어 있습니다. 여러 작업을 진행한다면 수정할 작업의 이름도 적습니다. 실행 중인 도구가 즉시 멈추는 것은 보장하지 않으며, Codex에 따라 현재 작업에 반영되거나 후속 순서로 처리될 수 있습니다. 원래 요청이 끝났다면 새 요청으로 처리합니다.

보고의 **작업 상세 보기**에는 파일명·설정·검증 기록 같은 설명이 들어갑니다. **첨부 이미지는 상세 밖에 바로 표시**되어 상세를 펼치지 않아도 볼 수 있습니다. 파일 경로만 적은 글은 실제 이미지 첨부를 대신하지 않습니다.

### 음원 미리듣기

음원은 담당자가 실제 파일을 보고에 첨부하면 **작업 상세 밖**에 카드로 표시됩니다. **▶ 음원 미리듣기 → 창 안의 재생 버튼** 순서로 직접 듣습니다. 자동 재생이나 AI 청취·전사는 없습니다. 자세한 요청문과 지원 형식은 [음원 첨부와 미리듣기](USER_GUIDE.ko.md#음원-첨부와-미리듣기)를 참고하세요.

## 기존 작업자 연결

작업자 채팅을 이미 만들어 뒀다면 다음 요청을 대신 사용합니다. 실제로 연결할 대화 이름을 함께 적으면 확인이 쉽습니다.

```text
이 프로젝트의 기존 총괄·기획자·디자이너·프로그래머·QA 대화를 찾아 줘.
내가 연결할 수 있도록 실제 대화 이름과 역할 후보를 표로 보여 줘.
확인한 기존 대화들을 이 프로젝트의 팀 회의실에 연결해 줘.
이 프로젝트의 작업 배정·질문·결과 공유에 필요한 담당자 간 연락을 허용할게.
새 작업자 채팅은 만들지 마.
```

후보가 여러 개면 원하는 대화를 지정합니다. 기존 팀은 실제 인원 구성에 맞춰 연결할 수 있으며, 새 팀 기본 양식과 똑같이 여섯 명을 채울 필요는 없습니다.

구성 변경도 총괄에게 문장으로 요청합니다. 예를 들어 **“이 담당자의 회의실 표시 이름과 역할을 바꿔 줘”**, **“작업을 인계한 담당자를 회의실에서 제외해 줘”**라고 할 수 있습니다. 바꾸려는 사람을 구체적으로 지정합니다. 진행 중인 작업·미답변 질문·파일 소유권·검증이 있으면 완료나 명시적 인계 후 제외합니다. 이때 바꾸는 표시 이름은 회의실 안의 이름이며, 기존 Codex 채팅 제목·모델까지 자동 변경하는 것은 아닙니다.

## 중단됐거나 잘 안 될 때

| 현상 | 다음에 할 일 |
| --- | --- |
| `node`, `git`, `codex` 명령을 찾지 못함 | 해당 도구 설치와 터미널 경로를 확인합니다. 새 터미널에서 `node --version`, `git --version`, `codex --version`으로 확인할 수 있습니다. |
| `codex plugin` 명령이 지원되지 않음 | 현재 Codex 설치의 플러그인 지원 여부를 확인합니다. 오류 문구를 그대로 알려 주고 지원되는 설치 방법을 확인합니다. |
| 설치했는데 팀 생성 기능을 못 찾음 | 최신 버전을 설치했는지 확인하고 Codex를 완전히 재시작합니다. 프로젝트 채팅에서 위의 생성 요청문을 보냅니다. |
| 생성 도구가 없다고 나옴 | 그 호스트에서는 새 대화창 생성이 제한된 상태입니다. 지원되는 Codex 환경을 사용하거나 실제로 만들어 둔 기존 채팅 연결을 요청합니다. |
| 모델을 고르라는 답변에서 멈춤 | 위의 방법 A 또는 B로 선택을 답하거나 역할별 모델을 구체적으로 지정합니다. |
| 담당자 일부만 만들어짐 | 아래의 재개 요청문으로 기존 구성 기록과 실제 생성 결과를 확인합니다. 처음부터 팀을 다시 만들라고 반복 요청하지 않습니다. |
| 만들려는 프로젝트가 다름 | 현재 진행을 멈추고 올바른 프로젝트를 지정합니다. 잘못 만든 채팅을 자동 삭제하거나 교체하지 않습니다. |
| 회의실에서 다른 프로젝트가 보임 | 상단 프로젝트와 현재 Codex 총괄 채팅을 모두 확인합니다. 해당 프로젝트의 총괄 채팅에서 회의실을 엽니다. |
| 사용량이 측정 불가로 나옴 | 실제 기록이 없거나 아직 완성되지 않았을 수 있습니다. 이는 0 사용량이라는 뜻이 아닙니다. |

중단 뒤에는 같은 구성을 진행하던 대화에서 다음처럼 요청합니다.

```text
이 프로젝트의 중단된 팀 구성 기록을 확인하고 이어서 진행해 줘.
이미 만든 대화창과 아직 결과를 확인하지 못한 대화창부터 구분해 줘.
전달 여부가 불확실한 작업자를 새 채팅으로 다시 만들지는 마.
기존 생성 결과를 확인해서 원래 계획에 연결해 줘.
```

실제 미생성이 확인되고 새 시도가 필요하면 이유와 모델 선택을 확인한 뒤 명시적으로 재시도를 요청합니다. 대기 시간이나 답변 누락만으로 미생성이라고 판단하지 않습니다.

## 업데이트와 사용량

플러그인을 처음 내려받은 `AI-team-meeting-room` 폴더에서 실행합니다.

```sh
git pull --ff-only
codex plugin add jyfood-room@jyfood-local
```

진행 중인 작업을 마치고 Codex를 완전히 종료·재실행합니다. 기존 회의실을 업데이트할 때마다 새 작업자 팀을 만들 필요는 없습니다.

설정 표와 기록의 저장·조회는 별도 AI를 호출하지 않습니다. 팀을 구성하는 총괄 대화, 새 채팅의 초기 역할 설정, 실제 작업·이미지 생성·분석·보고에는 정상 사용량이 발생합니다. 대기 상태를 확인하기 위한 정기 AI 호출은 추가하지 않습니다. 완료 후 담당자별 사용량은 실제로 연결된 기록이 있을 때 표시하며 누락된 수치를 추정하지 않습니다.

연결 정보와 생성 진행 기록은 기본적으로 사용자 홈의 `~/.codex/team-room`에 보관합니다. `TEAM_ROOM_HOME`을 지정했다면 그 위치를 사용합니다. 실제 채팅 ID·프로젝트 경로·기록을 GitHub에 올리거나 설정 예제에 붙여 넣지 않습니다.
