# 团队会议室：安装与使用说明

**简体中文** · [繁體中文](USER_GUIDE.zh-Hant.md) · [日本語](USER_GUIDE.ja.md) · [English](USER_GUIDE.en.md) · [한국어](USER_GUIDE.ko.md)

适用于 **0.17.0**。这是一个本地 Codex 插件，可将项目中的现有聊天连接成团队，在一个会议室中查看任务、提问、进度、图片、音频和结果。既可用于游戏，也可用于其他项目。用户向总负责人下达目标，需要参与的成员分别报告自己的工作。

## 1. 安装与更新

需要 Node.js 22 或更高版本、Git，以及支持本地插件和 MCP Apps 的 Codex。首次安装时，在用于存放插件源码的位置执行：

**0.17.0 更改了安装名称。** 已使用旧名称安装的用户，请先参阅[迁移步骤（韩语、英语）](MIGRATION.md)，再更新。

```sh
git clone https://github.com/yookyungsang/AI-team-meeting-room.git
cd AI-team-meeting-room
codex plugin marketplace add .
codex plugin add team-room@team-room-local
```

更新时，在同一插件源码文件夹执行：

```sh
git pull --ff-only
codex plugin add team-room@team-room-local
```

请先完成正在进行的工作，再完全退出并重新打开 Codex。更新插件不会删除现有聊天或会议记录。插件 ID 保持为 `team-room@team-room-local`，MCP 服务器名为 `team-room`。

## 2. 创建第一个团队

1. 打开**实际要开展工作的项目中的现有聊天**。插件源码项目与您的工作项目是两回事，请勿选错。
2. 请求：“打开此项目的团队会议室。”如果尚未连接，会显示已识别的项目名和团队未连接提示。
3. 选择 **菜单 → 创建基本团队**，确认项目、六个角色及模型和推理设置。
4. 点击 **确认说明 · 准备请求**。这一步只准备文本，不创建聊天，也不调用 AI。
5. 点击 **放入聊天输入框**，在原项目聊天中检查内容并**手动发送**。如果主机不支持放入草稿，请复制请求并粘贴到同一聊天中发送。
6. 连接完成后，留在这个原始聊天中下达第一个任务。

原始聊天会重命名并用作总负责人，保留它的记录、模型和推理设置。只会为策划、设计师、2 名程序员和 QA 创建 **5 个新聊天**。

| 角色 | 基本团队菜单的设置 |
| --- | --- |
| 总负责人 | 使用原始聊天，保留当前模型和推理设置 |
| 策划 | Codex 默认设置 |
| 设计师 | Codex 默认设置 |
| 程序员 1、2 | `gpt-6.1-sol` / `high` |
| QA 测试员 | `gpt-6-luna` / `medium` |

不支持的模型不会被自动替换。若要使用其他模型或已有成员，请在原始聊天中说明。正常工作期间不会为了补齐角色擅自创建新成员。

进度区域会显示这五名新成员的准备情况。首次连接过程中，会议室的任务输入会暂时不可用；仍可在原来的 Codex 聊天中提出停止或故障处理请求。再次点击创建基本团队按钮可关闭说明。

## 3. 中断或出错后继续

关闭窗口不会清除已保存的设置记录。选择 **中断或出错后继续**，在最初提出请求的总负责人聊天中确认继续请求并手动发送。

- 保留已经准备好的成员、原始模型选择和预留记录。
- 如果不确定聊天是否已经创建，先核对原始尝试和真实结果，不另建替代聊天。
- 如果设置仍在进行，请等待，不要反复创建另一个团队。
- 如果主机要求用户直接授权，菜单中的确认记录不能代替实际授权或绕过审批。

实际创建聊天、重命名和等待工具的权限，只能在支持的主机中执行获授权的操作时确认。连接检查通过不代表已经获得创建权限。

## 4. 日常工作

先确认会议室上方选择的项目。在底部输入目标、问题或修改意见，按 **Enter** 发送，按 **Shift+Enter** 换行。

```text
请让发货页面支持选择 1 个、5 个和 10 个。
小屏幕上的布局要清楚易用，并保留现有价格计算方式。
```

请求会发送给所选项目的总负责人。从其他聊天打开会议室时，可能会向已有总负责人转发一次。工作期间追加的指示会关联到原始任务。它会立即影响当前工作还是排队到下一轮，也取决于主机如何处理消息。

成员会直接记录自己的问题、回答、进度和完成结果。正文先用简单语言解释结果；准确的文件名、检查日志和技术依据放在 **查看工作详情** 中，点击展开只改变显示。

成员附上的图片显示在正文中，可点击放大。音频只在用户选择试听时加载，不会自动播放。最终图片和最终音频由制作者附在自己的完成报告中；中间图片仅在需要决定方向或说明问题时展示。插件不会自动收集其他聊天的附件。

## 5. 成员与协作规则

选择 **菜单 → 编辑成员**，从当前项目的已有聊天中添加成员、选择角色并保存。刷新列表只读取本地所属信息，不唤醒成员。总负责人的连接固定不变。正在工作、有未回答问题、持有文件占用权或正在验证的成员，需要先完成或明确交接，才能移除或更改角色。

策划负责系统、平衡和规则；设计师负责视觉、布局和交互判断；程序员负责实现和自查；QA 负责独立验证；总负责人负责分配与整合。简单修改不必召集所有人。程序员按实际需要分配，一人工作时按顺序进行，多人工作时划分文件和依赖，不同时修改同一文件或共享 Editor。有音源选择、制作、播放或音量判断时，才让已有的音响或音效成员参与。

文件保护和 Unity 验证需要总负责人先设置用户已授权的工作文件夹，并确认占用权与执行范围。插件不会在整个操作系统中锁住外部编辑器。程序员自查不能冒充独立 QA；同一错误不会无限重试。

## 6. 检查连接、暂停与删除

- **检查连接**：只读检查项目、总负责人、成员所属、未完成设置及主机的发送、草稿和通信支持，不创建聊天或调用 AI。
- **暂停新请求**：暂停新任务和分配，不取消 Codex 中已经开始的工作。
- **删除会议室**：先处理未完成工作，再从列表隐藏会议室并保留可恢复记录。实际成员聊天和项目文件不会删除。
- **已归档的会议室 → 恢复**：恢复原成员和记录，与导入 ZIP 是不同功能。

应用重启后出现多个同名会议室标签，不等于会议数据被复制。主机存在为同一会议室创建不同标签实例的路径。目前插件没有列出、合并主机已有标签的 API，尚未直接重现应用重启全过程。仅关闭多余标签不会删除已保存的会议记录。

## 7. ZIP 备份与导入

通过 **菜单 → 备份为 ZIP** 保存当前会议室的原始发言、工作详情、成员连接、图片和音频。解压后打开 `index.html` 可离线查看和试听。还包括 `meeting.md`、原始 JSON 和各文件的 SHA-256 校验列表。完整 ZIP 最大 128 MiB；支持下载的主机最多下载 16 MiB，更大文件可使用显示的本地保存路径。

会议室注册或记录丢失时：

1. 在**原项目的聊天**中打开会议室。原来的总负责人和成员聊天必须仍属于同一项目。
2. 选择 **菜单 → 导入备份 → 选择 ZIP 文件**，选择不超过 16 MiB 的 ZIP。更大的 ZIP 可通过 **通过本地路径导入** 输入绝对路径，最大 128 MiB。
3. 检查名称、成员数、请求数、发言数、图片数和音频数，以及无法恢复的原因。此时不会更改会议原记录。
4. 点击 **恢复已确认的会议室**。不会覆盖或合并现有会议室或记录，也不能恢复到其他项目。
5. 在上方选择恢复后的会议室，检查成员和记录。新请求处于暂停状态；确认后按需点击 **恢复新请求**。

含有未完成请求或任务的备份不能直接恢复为可工作的会议室，以免重新执行旧任务。可以离线查看 ZIP 中的 `index.html`，先处理任务，再创建新的可恢复备份。文件损坏、附件缺失或无法确认原成员所属时也会拒绝恢复。

导入中关闭窗口后，可选择 **检查之前准备的恢复 → 继续确认**。如果上传未完成，重新选择同一 ZIP，会从保存的位置继续。结果不确定时使用同一次恢复的确认按钮，不会自动重试。若发现更新的记录，会停止，不覆盖它们。

备份保存的是会议记录，不包含可自动恢复的工作文件夹授权、项目源文件、QA 控制台账、用量来源或实际 Codex 聊天。导入不会更改本地已有的控制和用量记录。若在其他环境继续工作，总负责人需要重新确认工作文件夹和验证环境；缺失用量不会被估算补齐。

## 8. 语言与用量

在 **菜单 → 界面语言 / Language** 中选择 한국어、English、日本語、简体中文或繁體中文。自动模式遵循浏览器语言。中文优先使用明确的 Hans/Hant 标记；没有标记时，TW/HK/MO 使用繁体，其他中文设置使用简体。其他不支持的语言显示英语，不查询地理位置。

界面语言切换不会翻译或改写已有发言、附件说明、正在输入的文本、模型或已保存的团队设置。工作报告遵循用户明确指定或原项目一直使用的语言。

插件在空闲、显示、语言切换、检查、备份或导入时不额外调用 AI。真正的工作和新团队初始化会产生正常用量。让模型阅读说明书也会使用普通上下文，因此只需读取相关部分。任务完成后，各成员用量根据实际观测记录显示；无法测量或相互重叠的记录不会猜测。

## 常见问题

| 情况 | 处理方法 |
| --- | --- |
| 没有自动选中会议室 | 检查是否在原项目的聊天中，以及团队是否已连接。存在多个候选或主机不支持时，请手动选择。 |
| 创建团队被拒绝 | 在原聊天中手动发送已准备的请求，检查原始尝试。不要绕过授权或替换不支持的模型。 |
| 添加列表中没有某个成员 | 检查其项目所属和归档状态，再刷新列表。不会列出所有其他项目的聊天。 |
| 发送结果不确定 | 使用请求 ID 在总负责人聊天中核对真实结果。不会自动重发，也不应连续重复发送同一内容。 |
| ZIP 恢复被拒绝 | 检查原项目、已有记录冲突、未完成任务、附件损坏和原成员所属。展开问题详情查看具体原因。 |

运行数据存放在 `~/.codex/team-room` 或 `TEAM_ROOM_HOME`，与源码文件夹分开。不要把真实连接、会议记录、ZIP 或个人截图提交到公开仓库。
