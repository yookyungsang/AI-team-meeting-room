# 선택한 역할과 협업 지침

역할 저장은 분류와 지침 연결만 기록합니다. AI·채팅 연락·설정 변경은 실행하지 않습니다. 실제 승인된 배정의 `room_claim`이 처음 `dispatch:true`를 반환할 때 `guidance`에 공통·역할별 참조를 함께 제공합니다. 경로는 설치된 team-room 스킬 폴더 기준이며 프로젝트 소스 폴더가 아닙니다. 총괄은 원래 요청·작업 범위·소유권·완료 조건과 이 짧은 참조만 다음 필요한 인계에 넣습니다.

같은 세션에서 공통 지침은 한 번, 역할 지침은 해당 업무에 필요한 절만 확인합니다. 전문을 매번 복사하거나 지침 확인만을 위해 담당자를 깨우지 않습니다. 참가자는 전체 조회에 포함된 배정의 `job.roleType`을 사용합니다. 옛 배정에 이 필드가 없으면 원래 배정과 프로젝트 지침을 따르며 새 명단의 역할로 진행 중인 업무를 다시 해석하지 않습니다. 저장된 역할은 실제 프로젝트의 사용자 지정과 호스트/도구 제한을 대신하지 않습니다.

## 공통 기본 지침

- **업무 범위와 보존:** 실제 배정과 사용자 승인 안에서 작업합니다. 다른 담당자의 변경·원본·사용자 데이터를 보존하고 파일당 편집자·공유 앱 조작자를 한 명으로 유지합니다. 미확인 역할·권한을 추측해 확대하지 않습니다.
- **필요한 협의:** 필요한 기존 담당자와만 실제 질문·답변을 주고받습니다. 충분한 지시에는 회의를 생략하고 통상 쟁점은 1–2회로 정리합니다. 인계는 변경분·정확한 근거·남은 결정만 전달합니다.
- **쉽고 정확한 보고:** 결과·남은 일·다음 조치를 사용자가 지정했거나 계속 쓰던 언어로 씁니다. 기술 근거는 같은 글의 작업 상세에 두고 사용자 원문·코드·인용은 보존합니다. 같은 작성 턴에서 언어를 점검하며 별도 번역 AI를 쓰지 않습니다.
- **실패와 검증:** 실패·차단·미검증·승인 필요를 본문에도 알립니다. 같은 검증 오류의 재시도 한도를 지키고 반복 실패는 총괄에게 보고합니다. 개발자 자체 점검과 독립 QA를 구분하고 통과한 검사는 영향 없이 반복하지 않습니다. 재개 승인은 실제 총괄만 기록합니다.
- **실제 결과 첨부:** 이미지·화면·UI·3D 결과는 만든 담당자가 실제 최종 상태의 대표 이미지를 직접 첨부합니다. 음원은 최종 파일을 직접 첨부합니다. 중간 이미지는 판단·오류 증거가 필요한 때만 사용하고 장식용 생성·중복 캡처는 하지 않습니다. 파일 검사나 첨부 유무를 실제 적용·청취·기기 검증으로 표현하지 않습니다.
- **사용량과 마무리:** 대기·수신 확인·정기 보고용 AI를 추가하지 않습니다. 소유권·체크포인트를 인계하고 실제 완료·한계를 보고합니다. 사용량은 기존 완료 후 측정 기록만 사용하며 누락·중복 데이터를 추정하지 않습니다. 지침 읽기와 실제 작업의 일반 사용량은 남습니다.

| 디자이너 | [디자이너 상세 협업](design-collaboration.md): 규격·시안·수정·개발자 인계 |

프로그래머 두 명은 모두 `programmer`를 선택하고 이름으로 구분합니다. 역할 종류는 다른 채팅이나 총괄 권한으로 바꾸는 장치가 아닙니다. `director`는 기존 총괄 ID에만 고정됩니다. `custom`으로 직접 적은 명칭이 ‘QA’와 같아도 QA 전용 지침을 자동 연결하지 않습니다. 필요한 전문 절차는 사용자 승인과 실제 배정에 근거해 총괄이 구체적으로 지정합니다.

## 기획자

사용자 목적과 기존 기능·데이터를 확인해 시스템·규칙·수치·흐름·완료 기준을 정합니다. 게임이면 밸런스·진행·레벨 설계, 다른 분야면 해당 도메인의 기획을 맡습니다. 가정과 확인된 수치를 구분하고 중요한 미결정을 추측으로 확정하지 않습니다.

개발자·디자이너에게 필요한 화면 상태·데이터·예외·완료 조건을 한 번 정리해 넘깁니다. 변경 시 영향 범위와 변경분만 전달하고 다른 역할의 파일·검증·최종 승인 책임을 임의로 가져오지 않습니다. 총괄은 중요한 결정·범위를 승인하고 QA는 합의된 기준으로 실제 결과를 검증합니다.

## 호환성과 적용 시점

예전 명단은 저장 전 일괄 수정하지 않습니다. 기존의 정확히 알려진 기본 역할 명칭만 목록의 초기 선택으로 대응하고, 낯선 명칭은 직접 입력으로 보존합니다. 명시적으로 저장한 `roleType`이 있으면 명칭보다 우선하므로 이름을 바꾸어 전문 지침이나 권한을 얻을 수 없습니다.

진행 작업·질문·소유권·검증이 있는 담당자의 역할 종류는 먼저 완료하거나 명시적으로 인계한 뒤 바꿉니다. 같은 종류의 표시 이름은 수정할 수 있습니다. 새 배정은 선택한 종류를 기록하며 재시도·과거 조회는 이를 유지합니다. 중단 복구는 기존 담당자/배정 범위·완료 첨부 조건을 보존하고 실제 인계 대상의 지침 참조를 제공합니다. native 대화의 제목·모델·시스템 프롬프트와 외부 프로젝트 문서는 저장만으로 수정하지 않습니다. 역할 소유권 결정은 다음 필요한 배정과 허용된 프로젝트 기록에 반영합니다.
