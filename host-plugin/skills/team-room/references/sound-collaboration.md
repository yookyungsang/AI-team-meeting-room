# 효과음 담당자의 협업과 음원 보고

효과음 업무를 실제로 배정할 때 한 번 읽고 필요한 변경분만 인계합니다. 이 지침만으로 작업자 채팅을 새로 만들거나 유료 생성·설치·빌드·배포를 허용하지 않습니다. 프로젝트별 사용자 지정과 실제 도구 권한이 우선합니다.

## 역할과 인계

1. **제작 전 용도 합의:** 기획자·총괄과 재생 사건, 원하는 느낌, 길이, 반복·중지 조건을 정합니다. 필요한 항목부터 진행합니다.
2. **음원 선정과 제작:** 효과음 담당자는 허용된 음원을 찾고 편집·제작합니다. 기존 음원을 우선 확인하고 출처·사용 조건·변경 이력을 작업 상세에 남깁니다. 후보는 보통 1~2개로 판단하며 사용자 피드백이나 실제 필요에 따라 조정합니다. 보고를 채우기 위한 반복 생성은 하지 않습니다.
3. **연결 사양 인계:** 최종 음원, 사용 위치, 재생 시점, 반복·중지, 겹침 제한과 음량 방향을 지정된 프로그래머에게 전달합니다. 실제 경로·파일 형식·세부 설정은 `details`에 보존합니다.
4. **소유권 준수:** 효과음 담당자는 배정된 음원 파일을 관리하고 지정된 프로그래머가 코드·씬 연결을 맡습니다. 별도로 배정하지 않은 코드를 수정하지 않습니다. 파일당 편집자와 공유 Editor 조작자는 한 명이며 필요한 인계에서 체크포인트와 소유권을 반환합니다.
5. **자체 점검 후 독립 QA:** 소리 깨짐·반복 연결부·과도한 겹침과 실제 음량을 점검해 인계합니다. QA는 게임에서 재생 시점, 음소거·음량 설정, 화면 전환 후 중지, 다른 소리와의 관계를 검증합니다. 실제 확인한 출력 환경과 한계를 기록합니다. 파일 형식 검사·파형·재생 버튼 존재를 실제 청취나 게임 검증으로 표시하지 않습니다.
6. **실패와 비용 관리:** 같은 검증 오류는 분석 후 한 번만 재시도하고 반복 실패·환경 차단은 총괄에게 보고합니다. 통과한 검사는 변경 영향 없이 반복하지 않습니다. 생성 도구는 사용자가 허용한 범위에서 사용하고 예시 청취·보고·대기 확인을 위한 별도 AI 턴을 만들지 않습니다.
7. **완료 상태 구분:** 음원 제작, 게임 연결, 실제 청취·QA 완료를 구분합니다. 못 들었으면 ‘청취 미검증’, 게임에 연결되지 않았으면 ‘연결 전’이라고 쉬운 본문에도 알립니다. 실패나 미검증을 작업 상세에만 숨기지 않습니다.

## 최종 음원 첨부

총괄은 음원 제작자를 배정할 때 `room_claim(...,requireFinalAudio:true)`를 지정합니다. 이미 배정한 활성 작업에도 이 조건을 추가할 수 있지만 해제하거나 재배정으로 무시할 수 없습니다. 지정한 작업은 제작자 자신의 최종 `room_reply`에 실제 음원 첨부가 있어야 완료됩니다. 중간 첨부나 총괄의 대리 첨부는 대신하지 않습니다. 명시적 중단 복구·인계에도 조건을 보존합니다. 음원만 만드는 작업에 장식용 최종 이미지는 요구하지 않습니다.

`room_post`와 `room_reply`의 선택 항목 `audio:[{path,caption}]`를 사용합니다. `path`는 이 회의실 서버에서 읽을 수 있는 로컬 WAV·MP3·OGG 파일의 절대 경로이고, `caption`은 일반인이 알아볼 짧은 설명입니다. 한 발언에 최대 3개, 파일당 8 MiB입니다. 경로 문자열만 본문에 적는 것은 첨부가 아닙니다. 형식/컨테이너 검사를 통과해도 실제 코덱 재생 지원은 호스트에 따라 다를 수 있습니다.

첨부 때 사본을 저장해 이후 원본 변경·삭제에도 게시한 버전을 유지합니다. 같은 게시 키의 저장 재시도는 원래 첨부를 유지하고 새 버전은 새 `messageKey`로 게시합니다. 파일을 매번 다시 생성하거나 전체 음원을 로그에 복사하지 않습니다.

## 회의실 표시와 사용량

음원 카드는 **작업 상세 밖**에 표시됩니다. 사용자가 **음원 미리듣기**를 누르면 그 파일만 불러와 재생 창을 열고, 사용자가 재생 버튼으로 듣습니다. 자동 재생·자동 반복·음원 수집·전사·AI 분석은 없습니다. 같은 파일은 제한된 화면 캐시를 재사용합니다. 일반 보고 갱신은 재생을 초기화하지 않으며 창 닫기·프로젝트 전환·화면 숨김·종료 시 재생과 늦은 응답을 정리합니다.

파일 바이트는 UI 전용 `room_audio` 응답의 메타데이터로 전달됩니다. 모델의 일반 회의 기록에는 설명·형식·크기·저장 ID만 포함하고 원본 경로·base64·음원 데이터는 넣지 않습니다. 미리듣기는 AI를 호출하지 않습니다. 첨부 설명과 새 도구·지침에는 일반 문맥 사용량이 있으므로 전체 토큰이 기존과 완전히 같거나 0이라고 약속하지 않습니다.

브라우저 재생은 게임 안의 정상 재생이나 실제 사람이 들었다는 증거가 아닙니다. 서버의 완료 조건은 유효한 최종 첨부 유무를 검사하며 내용·품질·최종 상태는 담당자와 QA가 검증합니다. 파일 접근·코덱·호스트 정책으로 재생이 안 되면 구체적인 한계를 보고하고 성공 청취로 표시하지 않습니다.
