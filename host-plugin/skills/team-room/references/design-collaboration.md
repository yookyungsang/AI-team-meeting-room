# 디자이너 전용 상세 협업 규칙

실제 시각 디자인 업무를 배정할 때 한 번 읽고, 이후에는 변경되거나 필요한 절만 확인합니다. 캐릭터·UI·배경·2D·3D 등 해당 작업의 항목만 적용합니다. 프로젝트의 사용자 지시·기존 규격·승인 범위와 도구 제한이 우선하며 특정 게임·엔진·외부 서비스에 의존하지 않습니다. 규칙 공지를 위한 호출이나 새 작업자 생성은 하지 않습니다.

## 1. 역할과 작업 범위

- 디자이너는 시각 방향·규격·배치·시안·제작 파일을, 기획자는 기능·게임 규칙·수치·밸런스를 맡습니다. 디자인을 맞추려고 기능이나 수치를 임의로 바꾸지 않습니다.
- 지정된 프로그래머는 자산 연결·화면 구현·자체 점검, QA는 실제 화면과 동작의 독립 검증, 총괄은 중요한 판단·통합·최종 승인을 맡습니다. 사용자가 달리 지정한 역할을 우선하고 없는 담당자를 만들지 않습니다.
- 담당 파일·검토자·인계 대상과 완료 기준을 다음 필요한 배정에 함께 정하고 프로젝트의 허용된 작업 기록에 남깁니다. 배정되지 않은 코드·씬·공용 자산은 수정하지 않습니다.

## 2. 제작 전 규격 확인

사용자 요청과 기존 자산·화면·관련 코드에서 확인된 내용을 재사용합니다. 아래 표는 작업에 해당하는 항목만 적는 기준이며, 모든 작업에 전체 표나 별도 문서를 만들라는 뜻이 아닙니다.

| 대상 | 확인할 내용 |
| --- | --- |
| 공통 | 사용 위치·목적, 대상 화면·기기, 스타일·참고 자료, 유지할 기존 요소, 제작 범위와 완료 기준 |
| 2D·이미지 | 실제 표시 크기와 비율, 파일 형식·해상도·투명 배경·여백, 편집 원본과 내보낼 파일 |
| UI | 필요한 화면·상태·버튼 동작, 작은 화면·안전 영역, 글자 길이·언어·가독성·접근성, 동적 수치·문구를 UI 텍스트로 분리할지 여부 |
| 3D | 사용할 엔진·버전과 형식, 크기·단위·방향·중심점, 메시·텍스처·재질 예산, 필요한 경우 리깅·관절·애니메이션·충돌체 조건 |
| 개발 연결 | 지정된 담당자, 파일 위치·이름, 가져오기 설정·자산 식별자 보존, 필요한 상태·크기·배치·연결 방식과 검증 환경 |

예산·규격은 실제 프로젝트와 개발자의 제약을 따릅니다. 다른 프로젝트의 해상도·텍스처 크기·엔진 설정을 그대로 강제하지 않습니다. 이미 확인된 사항을 다시 묻지 않고, 결과를 바꿀 필수 누락·충돌만 필요한 기획자·개발자에게 한 번에 질문합니다. 안전하게 정할 수 있는 선택은 근거를 기록하고 진행하며, 중요한 미결정을 추측으로 확정하지 않습니다. 무관한 독립 작업은 계속합니다.

## 3. 시안 제작과 검토

- 기존에 쓸 수 있는 자산을 먼저 확인하고 대표 시안 하나부터 검토합니다. 비교가 실제로 필요할 때만 후보를 추가하며, 매번 여러 장이나 모든 각도를 생성하지 않습니다. 3D 참고 시점도 모델링에 필요한 경우에만 늘립니다.
- 승인된 범위의 도구·스킬만 사용합니다. 이 지침은 유료 생성·추가 설치·업로드의 허가가 아니며 특정 생성 서비스를 의무화하지 않습니다. 사용한 도구·출처·확인된 사용 조건은 기존 작업 상세에 남기고 모르는 권리나 출처를 확보했다고 쓰지 않습니다.
- 중간 이미지는 사용자 요청, 시각적 선택, 중요한 변경·오류 증거가 필요할 때만 제작자 자신의 `room_post`에 첨부합니다. 기존 대표 이미지를 재사용하고 무엇을 볼지·미완성 부분·필요한 판단을 짧게 적습니다. 중간 시안을 최종 적용 화면처럼 표시하지 않습니다.
- 검토자는 용도 충족, 기존 스타일과의 일관성, 실제 표시 크기에서의 가독성, 구현 가능성을 중심으로 수정사항을 모아 전달합니다. 승인 범위 안의 일상 선택은 담당자끼리 해결하고, 범위·비용·핵심 방향의 변경이나 미해결 충돌만 총괄·사용자에게 필요한 판단을 요청합니다. 모든 단계를 별도 승인 회의로 만들지 않습니다.

## 4. 수정과 버전 보존

- 피드백을 수정할 항목·유지할 항목·확인이 필요한 항목으로 짧게 구분해 한 번의 수정 묶음으로 처리합니다. 후속 인계에는 변경분만 보내고 전체 시안·대화·로그를 다시 전달하지 않습니다.
- 기존 작업과 승인된 원본을 보존하고, 필요한 수정본은 구분 가능한 이름·버전으로 관리합니다. 승인된 파일 교체는 배정 범위와 해당 프로젝트의 자산·메타데이터 규칙에 따라 수행합니다. 같은 이름의 오래된 사본으로 덮어쓰지 않습니다.
- 파일당 편집자와 공유 앱 조작자는 한 명입니다. 공용 목록·카탈로그도 소유권을 정하고, 수정 중인 파일을 개발자가 동시에 교체하지 않도록 현재 버전·체크포인트·소유권을 인계합니다. 기존 추적 기록이 있으면 재사용하며 새 전역 원장이나 대량 해시 보고를 의무화하지 않습니다.
- 같은 방법의 동일 검증 오류는 원인 분석 후 최대 한 번만 재시도하고, 반복 실패·환경 차단은 근거와 함께 총괄에게 보고합니다. 창작상 선호 수정과 기술 실패 재시도를 구분합니다. 일상 협의는 보통 1–2회로 정리하되 미결정·새 요구·실제 결함을 횟수 때문에 숨기거나 완료 처리하지 않습니다. 이유 없는 무한 재생성은 하지 않습니다.

## 5. 개발자 인계

지정된 개발자에게 실제 파일과 구현에 필요한 정보만 한 번 전달합니다. 아래 양식은 기존 `details`나 프로젝트 작업 기록에 채울 수 있으며 별도 중복 문서·수신 확인 호출은 필요하지 않습니다. 해당하지 않는 항목은 생략합니다.

```text
목적 / 적용할 화면·상태 / 유지할 기능·수치:
파일·버전 / 편집 원본·내보낸 결과 / 확인된 출처·사용 조건:
2D·UI: 표시 크기·비율·여백·투명도 / 글자·동적 수치 / 상태·배치:
3D: 형식·단위·방향·중심점 / 메시·재질·텍스처 / 리깅·애니메이션:
가져오기·연결 설정 / 관련 자산 식별자·의존 파일:
자체 확인한 항목 / 미검증·남은 결정 / 실제 완료·검증 기준:
다음 담당자 / 파일·공유 앱 소유권 반환:
```

파일 경로·정확한 설정·로그 등은 작업 상세에 두고 본문에는 만든 것·아직 적용하지 않은 것·다음 할 일을 쉽게 설명합니다. 개발자는 최신 파일과 연결 규격을 확인하고, 구현 불가·성능 예산 충돌 등 실제 문제만 디자이너와 직접 조율합니다. 전달 성공이나 침묵을 승인·연결 완료로 간주하지 않습니다.

## 6. 적용 확인과 QA 인계

디자이너는 가능한 범위에서 결과 파일의 열림·형식·투명도·예상 크기를 점검하고, 개발자는 실제 가져오기·화면 연결·상태 전환을 자체 점검합니다. UI는 지정한 작은 화면·긴 문구·수치, 3D는 실제 크기·재질·필요한 동작 등 바뀐 항목을 확인합니다. 파일 검사·렌더 시안만으로 실제 앱이나 게임을 검증했다고 보고하지 않습니다.

개발자 자체 점검 후 변경 파일·예상 결과·재현 방법·검사 결과·남은 한계와 공유 앱 조작권을 QA에게 명시적으로 인계합니다. QA는 변경 영향에 맞춰 실제 환경을 독립 검증하고 결함은 재현 조건과 함께 해당 담당자에게 반환합니다. 수정 후에는 실패·새 영향 사례만 재검사하며 필요한 회귀는 유지합니다. QA·실행 환경이 없으면 미검증 범위를 밝히고 대체 확인을 독립 QA로 부르지 않습니다.

## 7. 완료 보고와 최종 이미지

디자인 제작, 앱·게임 연결, 실제 화면·기기 검증의 완료 상태를 구분합니다. 디자인만 끝났다면 ‘제작 완료·연결 전’처럼 본문에서도 알립니다. 총괄은 요구한 완료 기준과 실제 근거를 확인해 통합하며, 승인되지 않은 시안을 승인 완료로 표시하지 않습니다.

시각 결과를 만든 담당자는 자신의 최종 `room_reply`에 **해당 배정의 실제 최종 상태**를 보여 주는 대표 이미지 한 장을 반드시 직접 첨부합니다. 자산 제작 배정이면 최종 자산을, 화면 적용 배정이면 실제 적용 상태를 보여 주고 어떤 상태인지 밝힙니다. 경로만 적기·다른 채팅의 이미지·중간 시안·총괄의 대리 게시로 대신하지 않습니다. 총괄은 다음 필요한 배정에 `requireFinalImage:true`를 포함하며 조건과 차단은 복구·인계에도 유지합니다.

첨부 방법·접근 실패·불변 재시도는 [공통 이미지 규칙](../SKILL.md#images-during-work-and-at-completion)을 따릅니다. 이미지는 작업 상세 밖에 표시되고, 정확한 기술 정보는 같은 글의 상세에 보관합니다. 파일 접근·생성·캡처가 막히면 실제 한계를 게시하고 성공으로 마무리하지 않습니다. 첨부 유무 검사는 이미지 내용의 품질이나 실제 적용을 자동 인증하지 않습니다.

## 8. 사용량과 보고 언어

이 문서는 작성자·검토자의 협업 지침이며 새 자동 검사·모델 실행 기능이 아닙니다. 필요한 기존 담당자만 배정하고, 충분한 지시에는 추가 회의를 생략합니다. 같은 세션에서 전문을 반복해서 읽거나 전달하지 않고 변경분·근거 위치만 인계합니다. 규칙 확인·보고용 이미지·수신 확인·상태 조회를 위한 별도 AI 턴, 번역·요약 담당자, 정기 호출·자동 재전송은 추가하지 않습니다.

보고는 [사용자의 언어 유지 규칙](report-language.md)에 따라 기존 작성 턴에서 한 번 점검합니다. 지침을 읽고 실제 디자인을 제작·분석·보고하는 데는 일반 사용량이 있으므로 사용량 0이나 고정 절감률을 약속하지 않습니다. 사용량은 기존 완료 후 측정 기록만 사용하고 새 통계 보고 턴을 만들지 않습니다.
