# Local work controls · 0.4.1

Use these tools during authorized work, never as an idle AI loop. They share the existing project ID, configured member identities and external `TEAM_ROOM_HOME`. They do not create chats, send native messages, switch models or grant filesystem/build permissions. Configure an explicitly human-authorized workspace once; stored `workspacePath` alone is not authorization. Only the director configures, recovers, defines checks or approves a resume/exception. A member ID is a routing check, not independent caller authentication.

## Final visual deliverables · 0.4.1

For image creation, UI/screens, design or 3D output, set `room_claim(projectId, requestId, memberId=CREATOR, requireFinalImage=true)` during the existing assignment. If discovered later, add it to the active job once without resending; `dispatch:false` forbids another native assignment. The flag is persisted, cannot be removed, is included in compact status and recovery results, and follows interrupted work to its next owner. Unmarked historical/text jobs keep their existing behavior.

The creator must attach an actual final-state image to their own `room_reply(images=[{path,caption}])`. Neither a progress image nor another member's image satisfies this check; the director cannot accept while a marked creator job is unfinished/failed. An already posted final image need not be duplicated in the director's report. If generation/capture/file access is blocked, record a concrete `room_post(kind="blocker")` and `room_fail`, then use explicit authorized recovery if the block is resolved. Validation is local file/attachment presence, not automatic recognition of the true final pixels; the creator remains responsible for accurate final-state evidence. See [visual reporting](../SKILL.md#images-during-work-and-at-completion). No AI image watcher, reminders or collector is added.

## File ownership and safe writes

For audio production, `room_claim(...,requireFinalAudio:true)` requires the creator's final `room_reply(audio=[{path,caption}])`. Preview/director attachments do not substitute; explicit recovery preserves the flag for new or pending replacement jobs. Keep sound production, integration and real listening/QA separate under [sound collaboration](sound-collaboration.md). File validation is not a listening verdict. Preview is user-triggered and app-only, with no AI analysis or transcript.

1. `room_work(operation="configure", memberId="director", workspaceRoot=ABSOLUTE_AUTHORIZED_ROOT, unityCli=OPTIONAL_OFFICIAL_CLI_PATH)` enables controls for the selected project. Keep workspace and CLI paths in external runtime configuration, never source files.
2. Claim the native assignment with `room_claim` as before. Before editing, acquire a batch with `room_work(operation="acquire", requestId, memberId, key="files-1", paths=["Assets/Scripts/Example.cs", "Assets/Scenes/Example.unity"])`. It returns a persistent `leaseId` and current hashes. Conflicting ownership is rejected across rooms using the same runtime home, even if both rooms point to the same folder.
3. Read the current file through `room_work(operation="read", ..., path=RELATIVE_PATH)` as needed. For supported UTF-8 text edits, write with `operation="write"`, the exact `leaseId`, `path`, `expectedHash`, complete `content`, and a stable `key`. Changed ownership or a stale hash is rejected. Identical storage retries return the original receipt. Use `expectedHash="missing"` to create a new file. Writes are limited to 200 KB each. Do not use shell/file-edit tools to bypass the guarded writer for files managed by this workflow. Larger/binary files or edits requiring a native application need an explicit operator handoff and a disclosed enforcement limit.
4. At a meaningful handoff checkpoint, save `operation="checkpoint"`, `summary`, `nextSteps` (array) and the relevant relative `paths`. Save the current result and what remains; do not copy a transcript. Release with `operation="release"` and `leaseId` before completing the job or handing over to QA.

One active `@editor` lease excludes file edit leases under that workspace and other Editor leases. Acquire it after code owners release their leases. Return it after the operation. It serializes plugin-controlled Unity operations; a manually opened Unity Editor or unrelated editor can still save outside this plugin. These are enforced tool gates, not an OS-wide filesystem lock. A lease has no automatic expiry or takeover: elapsed time alone never proves a former writer stopped.

## Interrupted work and handoff

The director first verifies the original native task/process stopped. Do not infer this from a quiet chat, an old timestamp or another participant's completion. Then call `room_work(operation="recover", requestId, memberId="director", fromMemberId, toMemberId, confirmedStopped=true, reason, key="recovery-1")`. Both members must already exist in that project. The director identity stays in its existing director chat.

The response includes the saved checkpoint, remaining steps, formerly owned files with current hashes, and files changed since the checkpoint. Retain original scope, human constraints, failures and unverified work. Reacquire the required files before editing. Only the first `dispatch:true` permits one human-authorized native handoff to the returned existing chat/host; a repeated key gives `dispatch:false`. Do not automatically resend when native delivery is uncertain. Preserve the original request, routing and completed work. A superseded assignment is retained in history; the replacement participant posts their own result.

If no checkpoint exists, inspect the original request and actual current files rather than pretending a complete handoff exists. An interrupted Unity run must be reconciled separately before releasing its Editor lease. Crash recovery does not reconstruct unsaved editor buffers or restart a model automatically.

## Validation attempts and QA

The director defines an external/manual check once with `room_validation(operation="define", requestId, memberId="director", caseId="save-preservation", label="Save preservation", signature="stable acceptance target", required=true)`. Keep the returned canonical `caseId`. Renaming the same signature does not reset attempts. At execution, use `operation="begin"` with a unique stable `key`, then `operation="result"` with the returned `attemptId`, `status` (`passed`, `failed`, `blocked`, `unverified`), a short `summary`, and evidence locations.

The first failure permits at most one retry, with `analysis` required on the next begin. A repeated failure or an immediate environment block stops further starts. Neither a new turn nor a new request resets the case. Passing checks are not repeated without a director-recorded change. Only the director can `resume` with a concrete repair/environment reason, retaining previous attempts, or `waive` with an explicit reason and disclosed limitation. An exception is not a passing test. Required unresolved checks prevent a successful director completion; report failure with `room_fail` or record an honest exception rather than bypassing the gate.

These counters enforce runs registered through the tools. They cannot intercept arbitrary external test commands. QA must use begin/result around external verification and must not bypass a blocked case by renaming it or running commands directly. No extra model evaluates whether another attempt is needed.

## Unity automation

Configure the official **Unity CLI** executable, not the Unity Editor executable. Editors/licenses and the project's Unity Test Framework must already be available. The runner never installs an Editor, changes license settings or adds packages automatically. It uses `shell:false`, explicit project paths, hidden Windows helper processes and isolated external evidence directories.

With a valid `@editor` lease, use `room_validation(operation="unity", requestId, memberId, leaseId, key="play-1", mode="playmode", filter="Relevant.Tests", timeoutSeconds=600)`. Modes are `compile`, `editmode`, `playmode`, and `build`. Build supports `target` values `StandaloneWindows64`, `StandaloneLinux64`, `StandaloneOSX`, and `WebGL`; builds still require actual human authorization for that task. `headless=true` requests no graphics for compile/tests; do not use it as proof of visual/device behavior.

The tool starts one local process and returns an `attemptId`. There are no automatic validation retries (`--retries 0`). Status and evidence are visible in the normal room menu and `room_work(operation="status")`; do independent work or use native event waits instead of AI status polling. A project already open in another Editor is blocked. It must be safely handed off/closed before using this batch runner; do not kill another person's Editor. Compile/Console checks require an Editor-start log, zero exit and no detected error/exception patterns. Tests also require complete, consistent NUnit XML with executed, passing cases. Skipped, empty, missing or oversized evidence is not full success. Builds require a fresh nonempty artifact. These checks do not certify natural play, screenshots, real devices or every possible Console message format.

Runs of the same mode/filter/target retain attempt history independently of display names and request IDs. Repeated detected compiler/Console diagnostics also block new Unity modes/filters until director action. Unrelated manual checks can continue. Do not relabel failing evidence as success.

`operation="cancel"` stops only a live process owned by this server instance. After a server restart, never kill a stored PID: it may have been reused. The director verifies the old process stopped, then uses `operation="reconcile"`, `confirmedStopped=true`, and `reason` to mark an orphaned run blocked. Only then resume the check and release/reacquire ownership. Saved verdict receipts can finish materializing on a later local state read; that never launches a new run or AI turn.

## Participant usage after completion

Once per project setup, the director may call `room_usage(operation="discover", memberId="director")` to find only the already configured chats under the server host's local Codex sessions directory. An explicitly authorized alternative directory can be supplied in `file`. Or attach a particular existing JSONL with `operation="attach"`, `sourceMemberId`, and absolute `file`. Its embedded session identity must match that configured member. Missing local/remote records stay unavailable. Never start a second Codex/AI runtime to generate telemetry.

The importer consumes appended usage events locally and deduplicates by source/offset and cumulative totals. It keeps token counts, timestamps, turn IDs and tool-category tags, not messages, reasoning text or tool arguments. Official Codex exec `turn.completed.usage` is supported; native session `token_count` is a compatibility adapter and may be unavailable or change. Unknown or reset records are disclosed. A visible room reads appended records at most once per 10 seconds; hidden/closed rooms keep no watcher. `sync` is available when the user explicitly needs a fresh local read.

Show participant rows and the measured subtotal **after the original task is completed**, once in the final-result view. Do not add periodic AI usage reports or a second summary turn. The UI adds this view from local state, leaving the author's report unchanged. Token events arriving after the reply can update this same view. If that final model turn is not yet recorded, label the number partial. A source that cannot be read is unavailable, never zero. Whole-turn activity groups can indicate meeting, waiting or validation involvement, but mixed turns are not split into invented per-action costs. `room_usage(operation="label", sourceId, turnId, activity, memberId="director")` can classify a known whole turn when needed; normal work does not require a label call each turn.

Task reports exclude earlier chat history, and refuse to split overlapping tasks for the same chat. They are observed local token usage, not a complete account billing statement. `cached_input_tokens` is included in input and `reasoning_output_tokens` in output; do not add those subsets again. Missing sources, late events, unsupported schemas and mixed tasks limit coverage. Instructions/tool schemas and normal reporting still consume context; there is no promise of zero total usage or measured savings.

### Account quota alongside tokens

Existing native `rate_limits` metadata supplies account-wide usage/remaining percentages without another AI call. The final view keeps these percentages separate from participant token rows. A before/after change is computed only for compatible bucket, duration and non-null reset timestamps, with a near-start baseline and near-completion observation. Reset periods and missing baselines are not guessed. Other account activity may contribute, so a percentage-point change is not attributed exclusively to this task or divided by participant.

If local quota metadata is unavailable and the host provides a read-only native usage-limit tool (Codex `get_usage_limits`), the director may query it **once during its existing completion turn**, then call `room_usage(operation="record_limits", memberId="director", limits=[{bucket:"codex",window:"primary",usedPercent:OBSERVED_VALUE,windowDurationMins:OBSERVED_WINDOW,resetsAt:OBSERVED_RESET}])`. Copy only actual observed normalized windows. Omit unknown optional values. The store timestamps receipt by default; provide `observedAt` only when the actual observation time is known. Never pass account IDs, credit balances, tokens, guessed values or full raw account responses. Use `rateLimitsByLimitId` when available. This is a normal authorized tool/context cost, not a new model or idle polling loop. Do not wake a finished director solely to obtain a usage report. If unavailable, show unavailable.

## Runtime data

`work-control.json`, `usage-ledger.json` and `validation/<projectId>/<attemptId>/` live under `TEAM_ROOM_HOME` (normally `~/.codex/team-room`), outside the source. Back them up with the meeting records when needed. Never commit real runtime configuration, usage logs, paths, transcripts or screenshots. Existing room history and plugin/server identities stay unchanged.
