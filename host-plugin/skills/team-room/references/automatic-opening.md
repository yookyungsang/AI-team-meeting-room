# 프로젝트별 회의실 자동 선택

연결을 마친 로컬 Codex 프로젝트의 대화창에서 회의실 탭을 열면 그 프로젝트의 회의실을 자동 선택합니다. 총괄뿐 아니라 같은 프로젝트의 다른 사용자 대화창에서도 사용할 수 있습니다. 새 프로젝트는 기존 총괄·담당자를 한 번 연결해야 하며 자동 선택이 회의실이나 담당자를 생성하지는 않습니다.

## 확인하는 정보

현재 Codex의 도구 호출 메타데이터에 있는 여는 대화창 ID를 사용합니다. 지원 키는 thread_id/threadId 및 호환 별칭이고 x-codex-turn-metadata의 thread_id도 읽습니다. 값이 없거나 서로 다르거나 원격 호스트로 표시되면 자동 선택하지 않습니다. 이는 호스트 호환 정보이며 인증·연락·파일 권한을 부여하는 값이 아닙니다. 공개 thread entrypoint의 도구 인수는 비어 있으므로 호스트가 추가 메타데이터를 보내지 않는 환경에서는 선택창이 남습니다.

[읽기 전용 로컬 호환 어댑터](project-chat-catalog.md)에서 여는 대화창과 저장된 각 회의실 총괄의 명시적 프로젝트 소속을 비교합니다. 보관·내부 하위 작업·프로젝트 없음·다른 호스트·충돌 소속을 제외하고, 저장된 작업 폴더와 프로젝트 루트도 확인합니다. 일치하는 회의실이 정확히 하나일 때만 선택합니다. 같은 폴더·이름·최근 사용 기록·전역 활성 창·프로세스 작업 폴더만으로 추정하지 않습니다. 현재 대화창이 이미 회의실 구성원일 필요는 없지만 해당 프로젝트의 실제 사용자 채팅이어야 합니다.

## UI와 수동 선택

room_open에서 projectId를 직접 지정하면 그 값이 우선합니다. ID 없는 열기는 호스트 메타데이터로 확인하며, UI 최초 room_state(resolveCurrent:true)도 같은 확인을 한 번 수행해 초기 결과 전달 순서에 대응합니다. 일반 room_state()는 계속 선택창만 반환하고 자동 확인하지 않습니다. 선택 후 갱신과 모든 쓰기는 명시적 projectId를 사용합니다. 추가 도구·주기적 검색·AI 호출·새 대화창·자동 배정·글 전송은 없습니다.

표준 ui/notifications/tool-input의 최초 projectId도 받습니다. 사용자가 직접 선택을 바꾸거나 글을 쓰기 시작하면 늦은 자동 선택은 덮어쓰지 않습니다. 닫기·숨김·프로젝트 전환 후 늦은 결과도 기록이나 메시지를 다시 열지 않습니다. 프로젝트별 임시 입력과 표시 상태는 기존 분리 방식을 유지합니다. 호스트 채팅 자체를 다른 총괄 채팅으로 이동시키지 않으므로 실제 사용자 지시의 총괄 확인·한 번 전달 규칙은 그대로입니다.

미등록 프로젝트는 최초 연결 안내를, 같은 프로젝트의 여러 회의실은 선택 안내를 표시합니다. 지원하지 않는 Node/앱·메타데이터, 읽기 실패나 불분명한 소속도 선택창으로 돌아갑니다. 저장된 전체 목록의 첫 항목이나 마지막 사용 회의실을 대신 고르지 않습니다. 자동 선택은 저장된 명단·옵션·라우팅·작업·사용량 기록을 바꾸지 않습니다.

설치된 Codex의 threadId 전달 코드를 확인하고 격리된 합성 메타데이터·SQLite·UI 하네스로 검사합니다. 모든 Codex/원격 버전의 호환이나 실제 앱 화면 전환을 검증했다고 표시하지 않습니다. 일반 작업과 지침 문맥에는 기존 사용량이 있으며 자동 선택 자체는 모델을 호출하지 않습니다.
