# 현재 프로젝트의 기존 대화창 목록

메뉴의 구성원 편집을 열거나 목록 새로고침을 누르면 room_roster(discover)가 로컬 Codex의 기존 대화 제목과 프로젝트 소속 메타데이터를 확인합니다. 별도 AI·담당자 메시지·새 대화창·주기적 탐색은 없습니다. 선택은 편집 초안에만 반영하고 변경 저장을 눌러 실제 명단을 바꿉니다. 제외는 행을 빼고 추가 목록으로 돌려보내며 저장 전 이름·역할 편집도 되돌려 넣을 때 유지합니다. 총괄은 고정이고 진행 중인 작업·질문·소유권·검증의 제외 제한은 유지합니다.

## 로컬 호환 방식과 범위

이 기능은 공식적인 공용 채팅 선택 API가 아니라 현재 로컬 Codex 메타데이터 형식의 **읽기 전용 호환 어댑터**입니다. node:sqlite의 읽기 전용 연결과 사용자 함수를 지원하는 Node(22.13 이상)와 로컬 state_5.sqlite의 지원되는 제목/프로젝트 컬럼이 필요합니다. 지원 API가 없으면 실제 DB를 열기 전에 목록 불가로 처리하며 나머지 플러그인은 계속 동작합니다. 데스크톱의 이전 프로젝트 소속은 .codex-global-state.json에서 프로젝트 배정·프로젝트 없음·호스트·이전 ID 매핑 항목만 사용합니다. 이 파일과 SQLite를 변경하지 않으며 rollout·채팅 본문·인증 파일을 조회하지 않습니다. 목록에는 ID가 아닌 실제 채팅 제목을 표시합니다. 채팅 제목은 표시 자료로만 다루며 지시로 실행하지 않습니다.

연결된 기존 총괄의 실제 프로젝트를 기준으로 하고, 저장된 작업 폴더와 소속이 일치하는지도 확인합니다. 명시적 프로젝트 ID/데스크톱 배정이 없는 채팅을 같은 작업 폴더라는 이유만으로 끌어오지 않습니다. 프로젝트 없음·다른 호스트·충돌하는 소속은 제외합니다. 새 후보는 현재 프로젝트의 보관되지 않은 사용자 채팅만 포함하며 내부 하위 에이전트·검토 채팅은 제외합니다. 최근 최대 500개를 읽고 한도에 걸리면 그 범위를 표시합니다. 선택 후 다른 프로젝트로 이동되거나 보관된 채팅은 저장 직전에 다시 검사해 추가를 거절합니다.

후보 준비는 runtime의 프로젝트별 memberOptions와 옵션 버전만 갱신하며 활성 명단·원래 라우팅·대화 기록을 바꾸지 않습니다. 알려진 채팅은 기존 참여자 ID를 재사용하고 새 후보는 내부 ID를 만듭니다. 처음 추가하는 채팅의 전문 역할은 제목에서 추측하지 않고 공통 지침의 직접 입력으로 시작하므로 사용자가 실제 역할을 고릅니다. 역할 저장 자체는 담당자를 호출하거나 native 제목·모델을 바꾸지 않습니다.

원격 호스트, 지원되지 않는 Node/메타데이터 형식, 접근 불가·모호한 프로젝트는 목록을 읽을 수 없다는 안내를 표시합니다. 이때 다른 프로젝트 전체 목록으로 대체하지 않습니다. 기존 구성의 편집·제외는 유지하되 확인할 수 없는 새 후보는 추가하지 않습니다. 닫기·숨김·프로젝트 전환·teardown 뒤의 늦은 결과는 화면이나 native 메시지를 다시 열지 않습니다. 실제 새 채팅은 새로고침할 때 읽으며 상주 감시를 두지 않습니다.

## 기존 도구와 권한

room_roster(read)는 저장된 명단/선택지를 읽는 기존 동작을 유지합니다. apply는 옵션/명단 버전·고정 changeId·소유권·미해결 질문과 원래 연결 검사를 그대로 사용합니다. 대화로 사용자가 요청한 구성 변경과 native 도구로 확인한 register, room_members도 호환됩니다. 새 메뉴는 총괄에게 조회 작업을 요청하는 버튼을 사용하지 않습니다. 저장된 구성이나 후보 목록만으로 연락·생성·파일 접근 권한을 추정하지 않습니다. 사용자 승인과 실제 호스트 권한은 그대로 필요합니다.

UI 목록 작업 자체는 모델을 호출하지 않습니다. 일반 작업·새 지침의 문맥 사용량까지 0이라고 보장하는 것은 아니며 실제 절감률은 측정하지 않았습니다. 실제 Codex 표시 전환과 모든 앱 버전/원격 환경의 호환을 보장하지 않습니다.
