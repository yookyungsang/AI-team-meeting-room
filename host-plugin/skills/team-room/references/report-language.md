# 사용자의 언어를 유지하는 게시 전 점검

이 규칙은 특정 언어를 고정하지 않습니다. 담당자는 **현재 보고를 작성하는 같은 턴에서** 아래 내용을 한 번 확인하고 `room_post` 또는 `room_reply`로 게시합니다. 별도 번역·언어 판정 AI, 추가 검토 담당자, 정기 검사나 확인 왕복을 만들지 않습니다.

## 보고 언어를 정하는 기준

1. 사용자가 명시적으로 지정한 출력 언어를 우선합니다. 이후 명시적으로 바꿔 달라고 하면 새 지시를 따릅니다. 두 언어로 작성하라는 요청도 그대로 따릅니다.
2. 별도 지정이 없으면 해당 프로젝트·요청의 실제 사용자 대화에서 계속 사용해 온 언어를 유지합니다. 담당자는 총괄이 전달한 원래 사용자 요청과 보고 언어를 기준으로 삼습니다.
3. 아직 정해진 대화 언어가 없으면 원래 사용자가 작성한 설명의 언어를 기준으로 합니다. 같은 작업에 추가 지시가 들어와도 기존 보고 언어를 유지하며 명시적인 변경 요청을 우선합니다.
4. 인용한 문서·원문 로그·코드·파일명·제품명·복사한 다른 언어의 문장은 언어 변경 지시로 취급하지 않습니다. 플러그인 지침의 작성 언어, UI 언어, 위치·국가·시간대나 다른 담당자의 실수도 보고 언어를 정하는 근거가 아닙니다.

언어가 불명확하면 기존 보고 언어와 확인된 사용자 지시를 우선합니다. 실제로 결정이 필요한 경우에만 현재 턴에서 확인하고, 매번 언어를 다시 묻지 않습니다. 총괄은 다음 필요한 업무 배정·변경분 인계에 짧은 보고 언어 안내를 포함합니다. 이를 공지하려고 전원을 호출하거나 전체 대화를 복사하지 않습니다.

## 게시 직전 한 번 확인할 내용

- `text`의 일반 설명과 질문·답변이 사용자의 보고 언어로 자연스럽게 이어지는지 확인합니다. `details`의 설명 문장과 이미지·음원 설명에도 같은 기준을 적용합니다.
- 의도하지 않은 다른 언어의 문장이나 섞인 구절이 있으면 게시 전에 같은 작성 과정에서 고칩니다. 점검 과정 자체를 보고하거나 별도 점검 게시물을 만들지 않습니다.
- 정확한 코드, API, 파일명·경로, 모델·제품 이름, 원문 오류·인용문, 수치와 식별자는 보존합니다. 일반 설명과 원문 근거를 구분하고 필요한 원문은 `details`에 둡니다.
- 사용자가 직접 입력한 내용은 공백·줄바꿈까지 원문으로 유지합니다. 언어를 맞추기 위해 사용자 메시지나 과거 발언을 자동 번역·수정·재게시하지 않습니다.
- 실패·차단·미검증·승인 필요·권한 제한을 빠뜨리지 않습니다. 쉬운 표현과 보고 언어를 맞추더라도 협업에 필요한 기술 정보는 보존합니다.

예를 들어 한국어로 진행하던 작업에 일본어 로그가 붙으면 일반 설명은 한국어로, 영어로 진행하던 작업이면 영어로, 일본어로 진행하던 작업이면 일본어로 보고합니다. 필요한 원문 로그는 그대로 보존합니다. 이 예시는 실제 사용자 기록이 아닙니다.

## 적용 범위와 사용량

이것은 작성자의 자체 점검 규칙입니다. 서버가 언어를 자동 판정하거나 외국어 문자를 일괄 차단하는 기능이 아니며, 이미 게시된 기록을 바꾸지 않습니다. 저장 재시도는 기존 키와 본문을 그대로 사용합니다. 외국어를 쓰는 프로젝트나 정확한 원문 증거를 잘못 차단하지 않습니다.

별도 모델 호출·언어 탐지 서비스·번역 API·대기 작업은 추가하지 않습니다. 원래 보고 턴의 지침과 작성 과정에는 일반 문맥 사용량이 있으므로 전체 토큰이 기존과 정확히 같거나 언어 혼입을 100% 방지한다고 보장하지 않습니다. 반복 생성으로 완벽한 언어 점수를 맞추려 하지 않습니다.
