# 필요한 조회와 막힌 질문의 총괄 알림

## 변화 없는 빠른 반복 조회

room_get에는 실제 자신의 참여자 ID를 readerId로 포함합니다. 이는 캐시 범위 구분이며 독립적인 호출자 인증이나 권한 부여가 아닙니다. 같은 서버에서 **프로젝트·요청·담당자·조회 옵션**이 같고 반환할 내용도 같으면 첫 전체 조회 후 30초 동안 본문 대신 unchanged:true, 상태·미해결 질문 수·배정 상태와 재조회 간격만 반환합니다. 차단 오류를 내지 않으므로 같은 오류를 재시도하는 흐름을 만들지 않습니다. 이전에 읽은 내용을 사용하고 unchanged 응답을 다시 읽는 루프를 만들지 않습니다.

새 발언·결과·오류·추가 지시·명단 변경 등 조회 결과가 바뀌면 즉시 최신 내용을 반환합니다. 다른 담당자의 첫 조회, 다른 요청/옵션은 별도로 취급합니다. 판단·중단 복구·정확한 근거 확인·사용자 요청에 꼭 필요한 전체 재조회는 refreshReason을 각각 decision, recovery, evidence, user_request로 지정합니다. 컨텍스트 압축·새 턴 등으로 이전 원문을 사용할 수 없으면 recovery 또는 evidence로 필요한 내용을 다시 읽고 기억을 추측하지 않습니다. 일반 상태 확인을 이 이유로 위장하지 않습니다. 재조회 간격은 마지막 전체 응답부터 계산하고 반복 응답 때문에 계속 연장하지 않습니다.

캐시는 서버 메모리에 해시와 시각만 최대 256개 보관합니다. 원문·추가 지시를 지우거나 복사 저장하지 않으며 서버 재시작·항목 만료 뒤에는 다시 전체를 읽습니다. 첫 응답과 이미 짧은 statusOnly 응답에는 추가 캐시 정보를 붙이지 않습니다. 담당자 ID가 없는 예전 호출은 다른 사람의 첫 읽기를 가리지 않도록 기존 전체 응답을 유지합니다. UI의 room_state 갱신, 파일/검증 도구와 native read_thread·list_threads·wait_threads는 이 제한 대상이 아닙니다. 필요한 최초 조회와 실제 상태 확인·복구·QA 절차는 유지합니다. 제한은 전체 도구 호출 자체를 막는 기능이 아니며 짧은 도구 응답과 새 지침에도 일반 사용량이 있습니다.

## 회의실 원문과 한 번의 짧은 알림

실제로 진행을 막는 담당자의 question 또는 blocker를 room_post에 저장할 때 notifyDirector:true를 지정합니다. 원문 text·details, 원래 toMemberId·replyTo와 발언 순서는 그대로 보존합니다. 수신 확인·일상 진행·임의의 반복 알림에는 이 옵션을 쓰지 않습니다. 기존의 안정된 messageKey 또는 이미 알고 있는 실제 source ID로 같은 저장을 재시도합니다. 같은 발언의 알림 여부·내용·대상을 바꿀 수 없습니다.

첫 저장에서만 directorNotice.dispatch:true와 해당 프로젝트의 기존 총괄 채팅/호스트, 짧은 prompt가 반환됩니다. **직접 확인된 사용자 연락 승인**이 있을 때만 담당자가 native send_message_to_thread로 그 prompt를 그 대상에게 한 번 보냅니다. 서버는 메시지·AI를 직접 실행하거나 전송을 재시도하지 않습니다. 명단·알림 결과만으로 연락 권한을 추정하지 않습니다. 질문의 원래 수신자가 총괄이면 이 전송이 기존 peer 전송을 대신하므로 두 번 보내지 않습니다. 원래 대상이 다른 담당자이면 필요한 peer 전달은 유지하고 총괄 알림과 목적을 구분합니다. 알림이 질문의 답변 권한을 바꾸지는 않습니다.

같은 저장을 재시도하면 created:false, directorNotice.dispatch:false가 반환되며 prompt를 재발급하지 않습니다. 재시작·중복 호출도 새 알림을 허용하지 않습니다. 이는 한 번의 전달 허용 기록이지 실제 native 전달 성공이나 정확히 한 번의 수신 보장이 아닙니다. 저장 직후 중단되거나 native 전달 여부가 불확실하면 자동 재전송하지 말고 실제 native 기록으로 확인합니다. 전달이 안 됐다는 근거와 사용자 권한이 확인된 경우에만 기존 복구 절차에 따라 필요한 조치를 판단합니다. 질문은 회의실에 남고, 총괄은 활성 이벤트 대기도 유지합니다.

## 총괄이 알림을 받았을 때

[TEAM-ROOM-ALERT projectId requestId messageId]는 **기존 요청의 막힌 문제를 확인하라는 알림**입니다. 해당 프로젝트의 연결된 총괄인지 확인하고 room_get에 readerId=director, refreshReason=decision을 지정해 원래 요청·그 발언·현재 답변을 한 번 확인합니다. 완료된 요청, 이미 답변/결정된 알림은 재개·재배정하거나 확인 글을 추가하지 않습니다. 새 막힌 문제에는 자신의 필요한 판단만 기록하고, 다른 담당자의 질문이면 그 담당자를 사칭해 답하지 않습니다. 불필요한 전체 채팅 조회·재시작·새 담당자 생성·수신 확인 왕복은 하지 않습니다. 실패·미검증·승인·파일/Editor 소유권·독립 QA 기준은 그대로 적용합니다.
