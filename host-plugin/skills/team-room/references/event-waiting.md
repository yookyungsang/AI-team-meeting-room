# 완료·문제 중심 대기와 최소 조회

총괄은 완료·실패·진행을 막는 판단 요청·새 사용자 지시가 있을 때만 내용을 확인하고 개입합니다. 시간초과나 같은 진행 상태만으로 상황을 다시 분석하거나 담당자에게 진행 질문을 보내지 않습니다. 이 문서는 운영 지침이며 서버에 자동 호출·상주 감시·새 모델 실행기를 추가하지 않습니다.

## 배정과 대기

1. 최초 배정 때 원래 프로젝트·요청·담당자 ID, 기존 채팅/호스트, 수정 소유권·의존성과 완료 조건을 확인합니다. 같은 작업의 대기마다 채팅 목록·전체 이력·명단을 다시 찾지 않습니다. 중단 후에는 기존 표식으로 해당 요청과 필요한 체크포인트만 확인하고 이미 배정한 작업을 다시 보내지 않습니다.
2. 종료한 총괄을 완료·오류 시 재개하는 **실제 호스트 이벤트 기능**과 사용자 권한이 확인된 경우에만 그 기능으로 대기를 넘길 수 있습니다. 정상 결과뿐 아니라 예상치 못한 담당자 중단도 전달되는지 확인해야 합니다. 담당자가 직접 보내는 완료 메시지만으로는 응답할 수 없게 된 담당자의 중단을 발견할 수 없습니다. 단순히 총괄 턴을 끝내거나 회의실에 글을 저장했다고 자동 재개된다고 가정하지 않습니다.
3. 그 기능이 확인되지 않은 현재 로컬 연동에서는 활성 총괄이 native **wait_threads**로 완료·실패·주의 필요 이벤트를 기다립니다. 실제 진행 중인 대상을 호스트 한도 내에서 한 번에 묶고 각 대상의 최신 cursor를 이어갑니다. 끝난 대상은 다음 대기에서 제외하고 오류 대상은 정상 대기처럼 숨기지 않습니다. 대상별 별도 대기·전체 이력 조회를 병행하지 않습니다.
4. 호스트와 현재 대화의 응답성/실행 제한이 허용하면 짧은 시간을 강제 지정하지 않고 도구의 지원되는 기본 이벤트 대기를 사용합니다. 현재 도구 설명의 기본값은 120000ms이며 새 사용자 입력은 대기를 일찍 끝냅니다. 더 짧은 제한이 있으면 그 제한을 우선합니다. 지원이 확인되지 않은 긴 timeout이나 무기한 대기를 만들지 않습니다. **timeoutMs:0 반복, 임의의 짧은 간격 조회, 60초 고정 반복을 기본 정책으로 강제하지 않습니다.**
5. 시간초과에 변화가 없으면 반환된 cursor만 이어서 같은 이벤트 대기를 계속하거나 독립된 승인 업무를 합니다. 추가 room_get·read_thread·list_threads·room_state·진행 질문·진행 요약·재배정을 하지 않습니다. 진행 문구만 바뀌어도 개입할 이유가 없으면 조회를 확대하지 않습니다. 대기 자체와 도구 반환에는 일반 문맥 사용량이 남습니다.

## 이벤트가 왔을 때

- **완료:** 전달된 담당자 결과를 한 번 검토하고 실제 의존 작업·검증·통합만 진행합니다. 회의실 저장 여부가 필요하면 room_get(statusOnly:true)을 한 번 사용합니다. 정확한 결정에 필요한 본문/근거만 읽고 이미 전달된 전체 최종 글을 재수집하지 않습니다. 최종 이미지·음원 조건, 독립 QA와 미검증 사실은 유지합니다.
- **실패·주의 필요·판단 요청:** 해당 담당자와 실패/질문만 확인합니다. 승인 요청을 대신 승인하거나 오류를 성공으로 바꾸지 않습니다. 중단은 실제 호스트 상태로 확인하고 기존 복구·재시도 한도와 파일/Editor 소유권 절차를 따릅니다. 조회 오류나 접근 불가는 한계를 알리고 같은 실패 조회를 반복하지 않습니다.
- **새 사용자 지시:** 원래 요청의 추가 지시를 필요한 판단/통합 시점과 최종 보고 전에 확인합니다. 원래 일을 재시작하지 않고 변경분만 기존 담당자에게 전달합니다. 사용자 입력을 놓치지 않도록 호스트의 조정/대기 동작과 현재 도구 제한을 우선합니다.

담당자는 의미 있는 진행을 회의실에 직접 기록하되, 일상 진행·수신 확인·‘게시했습니다’만으로 총괄에게 native 메시지를 또 보내지 않습니다. 완료 이벤트가 결과를 전달했다면 별도 완료 알림도 보내지 않습니다. 다른 작업을 막는 실제 질문·결정·문제만 검증된 사용자 연락 승인 안에서 필요한 대상에게 한 번 전달합니다. 서버 저장은 native 전달 성공의 증거가 아니며 불확실한 전달을 자동 재전송하지 않습니다.

총괄은 일이 남아 있는 상태를 완료로 표시하거나 대기 횟수만 줄이려고 조정 턴을 끝내지 않습니다. 호스트가 종료한 턴의 재개를 지원하지 않으면 그 한계를 밝히고 활성 이벤트 대기를 유지합니다. heartbeat·cron·진행 확인용 AI·우회 런타임을 만들지 않습니다. 실제 사용량은 완료 후 관찰 기록으로만 표시하며 0 또는 특정 절감률을 보장하지 않습니다.
