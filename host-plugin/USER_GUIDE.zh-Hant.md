# 團隊會議室：安裝與使用說明

**繁體中文** · [简体中文](USER_GUIDE.zh-Hans.md) · [日本語](USER_GUIDE.ja.md) · [English](USER_GUIDE.en.md) · [한국어](USER_GUIDE.ko.md)

適用於 **0.16.1**。這是一個本機 Codex 插件，可將專案中的現有聊天連接成團隊，在同一會議室查看任務、提問、進度、圖片、音訊與結果。既可用於遊戲，也可用於其他專案。使用者向總負責人下達目標，需要參與的成員各自回報自己的工作。

## 1. 安裝與更新

需要 Node.js 22 或更新版本、Git，以及支援本機插件與 MCP Apps 的 Codex。首次安裝時，在存放插件原始碼的位置執行：

```sh
git clone https://github.com/yookyungsang/AI-team-meeting-room.git
cd AI-team-meeting-room
codex plugin marketplace add .
codex plugin add jyfood-room@jyfood-local
```

更新時，在同一插件原始碼資料夾執行：

```sh
git pull --ff-only
codex plugin add jyfood-room@jyfood-local
```

請先完成正在進行的工作，再完全結束並重新開啟 Codex。更新插件不會刪除現有聊天或會議記錄。插件 ID 維持 `jyfood-room@jyfood-local`，MCP 伺服器名稱為 `team-room`。

## 2. 建立第一個團隊

1. 開啟**實際要進行工作的專案中的現有聊天**。插件原始碼專案與您的工作專案是兩回事，請勿選錯。
2. 請求：「開啟此專案的團隊會議室。」如果尚未連接，會顯示已辨識的專案名稱與團隊未連接提示。
3. 選擇 **選單 → 建立基本團隊**，確認專案、六個角色及模型與推理設定。
4. 點擊 **確認說明 · 準備請求**。此步驟只準備文字，不建立聊天，也不呼叫 AI。
5. 點擊 **放入聊天輸入框**，在原專案聊天中檢查內容並**手動傳送**。如果主機不支援放入草稿，請複製請求並貼到同一聊天中傳送。
6. 連接完成後，留在這個原始聊天中下達第一個任務。

原始聊天會重新命名並用作總負責人，保留它的記錄、模型與推理設定。只會為企劃、設計師、2 名程式設計師與 QA 建立 **5 個新聊天**。

| 角色 | 基本團隊選單的設定 |
| --- | --- |
| 總負責人 | 使用原始聊天，保留目前模型與推理設定 |
| 企劃 | Codex 預設設定 |
| 設計師 | Codex 預設設定 |
| 程式設計師 1、2 | `gpt-6.1-sol` / `high` |
| QA 測試員 | `gpt-6-luna` / `medium` |

不支援的模型不會被自動替換。若要使用其他模型或已有成員，請在原始聊天中說明。正常工作期間不會為了補齊角色擅自建立新成員。

進度區域會顯示這五名新成員的準備情況。首次連接過程中，會議室的任務輸入會暫時無法使用；仍可在原來的 Codex 聊天中提出停止或問題處理請求。再次點擊建立基本團隊按鈕可關閉說明。

## 3. 中斷或出錯後繼續

關閉視窗不會清除已儲存的設定記錄。選擇 **中斷或出錯後繼續**，在最初提出請求的總負責人聊天中確認繼續請求並手動傳送。

- 保留已準備好的成員、原始模型選擇與預留記錄。
- 如果不確定聊天是否已建立，先核對原始嘗試與真實結果，不另建替代聊天。
- 如果設定仍在進行，請等待，不要反覆建立另一個團隊。
- 如果主機要求使用者直接授權，選單中的確認記錄不能代替實際授權或繞過審核。

實際建立聊天、重新命名與等待工具的權限，只能在支援的主機中執行獲授權的操作時確認。連接檢查通過不代表已獲得建立權限。

## 4. 日常工作

先確認會議室上方選擇的專案。在底部輸入目標、問題或修改意見，按 **Enter** 傳送，按 **Shift+Enter** 換行。

```text
請讓出貨頁面支援選擇 1 個、5 個和 10 個。
小螢幕上的配置要清楚易用，並保留現有價格計算方式。
```

請求會傳給所選專案的總負責人。從其他聊天開啟會議室時，可能會向已有總負責人轉送一次。工作期間追加的指示會關聯至原始任務。它會立即影響目前工作，還是排隊到下一輪，也取決於主機如何處理訊息。

成員會直接記錄自己的問題、回答、進度與完成結果。本文先以簡單語言解釋結果；精確的檔案名稱、檢查日誌與技術依據放在 **查看工作詳情** 中，點擊展開只改變顯示。

成員附上的圖片顯示在本文中，可點擊放大。音訊只在使用者選擇試聽時載入，不會自動播放。最終圖片與最終音訊由製作者附在自己的完成報告中；中間圖片僅在需要決定方向或說明問題時展示。插件不會自動收集其他聊天的附件。

## 5. 成員與協作規則

選擇 **選單 → 編輯成員**，從目前專案的現有聊天中新增成員、選擇角色並儲存。重新整理清單只讀取本機所屬資訊，不喚醒成員。總負責人的連接固定不變。正在工作、有未回答問題、持有檔案占用權或正在驗證的成員，需要先完成或明確交接，才能移除或變更角色。

企劃負責系統、平衡與規則；設計師負責視覺、配置與互動判斷；程式設計師負責實作與自查；QA 負責獨立驗證；總負責人負責分配與整合。簡單修改不必召集所有人。程式設計師依實際需要分配，一人工作時按順序進行，多人工作時劃分檔案與相依性，不同時修改同一檔案或共用 Editor。有音源選擇、製作、播放或音量判斷時，才讓已有的音響或音效成員參與。

檔案保護與 Unity 驗證需要總負責人先設定使用者已授權的工作資料夾，並確認占用權與執行範圍。插件不會在整個作業系統中鎖住外部編輯器。程式設計師自查不能冒充獨立 QA；同一錯誤不會無限重試。

## 6. 檢查連接、暫停與刪除

- **檢查連接**：唯讀檢查專案、總負責人、成員所屬、未完成設定及主機的傳送、草稿與通訊支援，不建立聊天或呼叫 AI。
- **暫停新請求**：暫停新任務與分配，不取消 Codex 中已開始的工作。
- **刪除會議室**：先處理未完成工作，再從清單隱藏會議室並保留可還原記錄。實際成員聊天與專案檔案不會刪除。
- **已封存的會議室 → 還原**：還原原成員與記錄，與匯入 ZIP 是不同功能。

應用程式重新啟動後出現多個同名會議室分頁，不等於會議資料被複製。主機存在為同一會議室建立不同分頁實例的路徑。目前插件沒有列出、合併主機現有分頁的 API，尚未直接重現應用程式重新啟動的完整過程。僅關閉多餘分頁不會刪除已儲存的會議記錄。

## 7. ZIP 備份與匯入

透過 **選單 → 備份為 ZIP** 儲存目前會議室的原始發言、工作詳情、成員連接、圖片與音訊。解壓縮後開啟 `index.html` 可離線檢視與試聽。還包括 `meeting.md`、原始 JSON 與各檔案的 SHA-256 檢查清單。完整 ZIP 最大 128 MiB；支援下載的主機最多下載 16 MiB，更大檔案可使用顯示的本機儲存路徑。

會議室註冊或記錄遺失時：

1. 在**原專案的聊天**中開啟會議室。原來的總負責人與成員聊天必須仍屬於同一專案。
2. 選擇 **選單 → 匯入備份 → 選擇 ZIP 檔案**，選擇不超過 16 MiB 的 ZIP。更大的 ZIP 可透過 **透過本機路徑匯入** 輸入絕對路徑，最大 128 MiB。
3. 檢查名稱、成員數、請求數、發言數、圖片數與音訊數，以及無法還原的原因。此時不會變更會議原記錄。
4. 點擊 **還原已確認的會議室**。不會覆寫或合併現有會議室或記錄，也不能還原至其他專案。
5. 在上方選擇還原後的會議室，檢查成員與記錄。新請求處於暫停狀態；確認後視需要點擊 **恢復新請求**。

含有未完成請求或任務的備份不能直接還原為可工作的會議室，以免重新執行舊任務。可以離線檢視 ZIP 中的 `index.html`，先處理任務，再建立新的可還原備份。檔案損壞、附件缺失或無法確認原成員所屬時也會拒絕還原。

匯入時關閉視窗後，可選擇 **檢查先前準備的還原 → 繼續確認**。如果上傳未完成，重新選擇同一 ZIP，會從儲存的位置繼續。結果不確定時使用同一次還原的確認按鈕，不會自動重試。若發現更新的記錄，會停止，不覆寫它們。

備份儲存的是會議記錄，不包含可自動還原的工作資料夾授權、專案原始檔案、QA 控制台帳、用量來源或實際 Codex 聊天。匯入不會變更本機已有的控制與用量記錄。若在其他環境繼續工作，總負責人需要重新確認工作資料夾與驗證環境；缺失用量不會被估算補齊。

## 8. 語言與用量

在 **選單 → 介面語言 / Language** 中選擇 한국어、English、日本語、简体中文或繁體中文。自動模式遵循瀏覽器語言。中文優先使用明確的 Hans/Hant 標記；沒有標記時，TW/HK/MO 使用繁體，其他中文設定使用簡體。其他不支援的語言顯示英語，不查詢地理位置。

介面語言切換不會翻譯或改寫已有發言、附件說明、正在輸入的文字、模型或已儲存的團隊設定。工作報告遵循使用者明確指定或原專案一直使用的語言。

插件在閒置、顯示、語言切換、檢查、備份或匯入時不額外呼叫 AI。真正的工作與新團隊初始化會產生正常用量。讓模型閱讀說明書也會使用一般上下文，因此只需讀取相關部分。任務完成後，各成員用量依實際觀測記錄顯示；無法測量或彼此重疊的記錄不會猜測。

## 常見問題

| 情況 | 處理方法 |
| --- | --- |
| 沒有自動選取會議室 | 檢查是否在原專案的聊天中，以及團隊是否已連接。存在多個候選或主機不支援時，請手動選擇。 |
| 建立團隊遭拒 | 在原聊天中手動傳送已準備的請求，檢查原始嘗試。不要繞過授權或替換不支援的模型。 |
| 新增清單中沒有某個成員 | 檢查其專案所屬與封存狀態，再重新整理清單。不會列出所有其他專案的聊天。 |
| 傳送結果不確定 | 使用請求 ID 在總負責人聊天中核對真實結果。不會自動重送，也不應連續重複傳送同一內容。 |
| ZIP 還原遭拒 | 檢查原專案、已有記錄衝突、未完成任務、附件損壞與原成員所屬。展開問題詳情查看具體原因。 |

執行資料存放在 `~/.codex/team-room` 或 `TEAM_ROOM_HOME`，與原始碼資料夾分開。不要將真實連接、會議記錄、ZIP 或個人截圖提交至公開儲存庫。
