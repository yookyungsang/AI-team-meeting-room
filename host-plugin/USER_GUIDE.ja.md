# チーム会議室：インストールと使い方

**日本語** · [한국어](USER_GUIDE.ko.md) · [English](USER_GUIDE.en.md) · [简体中文](USER_GUIDE.zh-Hans.md) · [繁體中文](USER_GUIDE.zh-Hant.md)

バージョン **0.17.0**。Codexのプロジェクト内のチャットをチームとして接続し、依頼・質問・進捗・画像・音声・結果を一か所で確認するローカルプラグインです。ゲーム以外のプロジェクトでも利用できます。最初に総括へ目標を送り、必要な担当者が自分の作業を直接報告します。

## 1. インストールと更新

Node.js 22以上、Git、ローカルプラグインとMCP Appsに対応したCodexが必要です。初回はプラグインのソース用フォルダーで実行します。

**0.17.0でインストール名が変わりました。** 旧名でインストール済みの場合は、更新前に[移行手順（韓国語・英語）](MIGRATION.md)を確認してください。

```sh
git clone https://github.com/yookyungsang/AI-team-meeting-room.git
cd AI-team-meeting-room
codex plugin marketplace add .
codex plugin add team-room@team-room-local
```

更新するときは、このソースフォルダーで次を実行します。

```sh
git pull --ff-only
codex plugin add team-room@team-room-local
```

進行中の作業を終えてからCodexを完全に終了し、開き直してください。インストールの更新だけでは既存チャットや会議記録を削除しません。プラグインIDは `team-room@team-room-local`、MCPサーバー名は `team-room` です。

## 2. 最初のチームを作る

1. **実際に作業するプロジェクト内の既存チャット**を開きます。プラグインのソース用プロジェクトと、作業対象のプロジェクトを取り違えないでください。
2. 「このプロジェクトのチーム会議室を開いて」と依頼します。未接続なら、確認できたプロジェクト名とチーム未接続の案内が表示されます。
3. **メニュー → 基本チームを作成**を選び、プロジェクト名、6つの役割、モデル・推論設定を確認します。
4. **説明を確認・依頼文を準備**を押します。依頼文の準備だけではチャットを作成せず、AIも呼び出しません。
5. **チャット入力欄に入れる**を押し、元のプロジェクトのチャットで内容を確認して**自分で送信**します。挿入に未対応のホストでは、依頼文をコピーして同じチャットに貼り付けます。
6. 接続が完了したら、この元のチャットで最初の作業を指示します。

現在のチャットを総括として使い、名前を変更します。総括の履歴・モデル・推論設定は維持し、企画担当・デザイナー・プログラマー2名・QAの**5つの新規チャットだけ**を作成します。

| 役割 | 基本メニューの設定 |
| --- | --- |
| 総括ディレクター | 元のチャットと現在のモデル・推論設定を維持 |
| 企画担当 | Codexの既定設定 |
| デザイナー | Codexの既定設定 |
| プログラマー 1・2 | `gpt-6.1-sol` / `high` |
| QA担当 | `gpt-6-luna` / `medium` |

未対応のモデルを別のモデルに自動置換しません。別のモデルや既存の担当者を使う場合は、元のチャットで希望を伝えてください。通常の作業中に不足する担当者を勝手に新設することはありません。

進捗画面では新規5名の準備状態を表示します。初回の接続中は会議室の作業入力を待機させますが、元のCodexチャットでは中止や問題の相談ができます。基本チームのボタンをもう一度押すと説明を閉じます。

## 3. 中断・エラーからの再開

画面を閉じても保存済みの設定記録は残ります。**中断・エラー後に再開**を選び、最初に依頼した総括チャットで再開の依頼文を確認して直接送信します。

- すでに準備済みの担当者と元のモデル選択を維持します。
- 作成済みか不明なチャットを新しく作り直しません。元の試行と実際の結果を先に確認します。
- まだ設定中なら、そのまま待ちます。ボタンを繰り返し押して別チームを作らないでください。
- ホストが直接のユーザー指示を要求した場合、メニュー内の確認記録で承認を迂回しません。

実際のチャット作成・名前変更・イベント待機の権限は、対応ホストでの承認された操作時に確認されます。接続点検の成功だけでは作成権限を保証しません。

## 4. 毎日の作業

会議室上部でプロジェクトを確認し、下の入力欄に目標・質問・修正内容を書いて **Enter** で送信します。**Shift+Enter** で改行します。

```text
発注画面で数量を1個、5個、10個から選べるようにしてください。
小さな画面でも迷わない配置にして、既存の価格計算は維持してください。
```

依頼は選択したプロジェクトの総括に送られます。別のチャットから開いていれば、既存の総括へ一度転送される場合があります。作業中の追加指示は元の依頼に結び付きます。現在の作業に反映されるか、次のターンまで待つかはホストのメッセージ処理にも依存します。

担当者の質問・回答・進捗・完了報告を確認してください。わかりやすい本文の下の **作業の詳細を表示** で、正確なファイル名や検証記録を展開できます。これは表示操作だけです。

画像は担当者の添付として本文に表示され、クリックで拡大できます。音声は再生を選んだときだけ読み込み、自動再生しません。完成画像・最終音声は制作担当者が自分の完了報告に添付します。途中の画像は判断や問題確認に必要なときだけ使います。他のチャットの添付を自動収集しません。

## 5. メンバーと協業の規則

**メニュー → メンバーを編集**で、現在のプロジェクトの既存チャットを追加し、役割を選んで保存します。一覧更新はローカルの所属情報を読み、担当者を起こしません。総括の接続は固定です。作業・未回答の質問・ファイル占有・検証が残る担当者は、その完了または明示的な引き継ぎ後に除外・役割変更します。

企画担当はシステムやバランス、デザイナーは見た目・配置・操作の判断、プログラマーは実装と自己点検、QAは独立検証を担当し、総括が統合します。小さな修正で全員を呼びません。プログラマーは実際に必要な人数だけ割り当て、同じファイルや共有Editorを同時に編集しません。音の選択・制作・音量判断が必要なら、既存の音響・効果音担当が参加します。

ファイル保護・Unityの検証は、総括が人間に許可された作業フォルダーを設定し、必要な占有と実行範囲を確認してから使います。外部エディターをOS全体でロックする機能ではありません。自己点検を独立QAの完了とは扱わず、失敗した検証の無制限な再試行はしません。

## 6. 接続点検・一時停止・会議室の削除

- **接続を点検**：プロジェクト、総括、担当者の所属、未完了の設定、ホストの送信・下書き・通信対応を読み取り専用で確認します。チャット作成やAI呼び出しはありません。
- **新規依頼を一時停止**：新しい依頼・割り当てを止めます。すでに進行中のCodexの作業は取り消しません。
- **会議室を削除**：進行中の作業を整理した後、一覧から隠して記録を保管します。実際の担当者チャットとプロジェクトファイルは残ります。
- **保管した会議室 → 復元**：同じ担当者と記録を戻します。ZIPの読み込みとは別の操作です。

アプリ再起動後に上部の会議室タブが重複する現象は、会議データの複製とは区別します。ホストは同じ会議室を別インスタンスのタブとして開く経路を持ちます。プラグインにはホストの既存タブを列挙・統合するAPIがなく、再起動の実機再現は未確認です。余分なタブだけを閉じても保存済みの会議記録は消えません。

## 7. ZIPバックアップと読み込み

**メニュー → ZIPでバックアップ**で、選択した会議室の元の発言・作業詳細・担当者接続・画像・音声を保存します。ZIPを展開して `index.html` を開くと、オフラインで閲覧・試聴できます。`meeting.md`、元のJSON、ファイルごとのSHA-256一覧も含みます。完全なZIPは最大128 MiB、ホストへのダウンロードは対応環境で16 MiBまでです。大きいファイルは表示されたローカルパスを使います。

会議室の登録や記録が失われた場合：

1. **元のプロジェクトのチャット**で会議室を開きます。元の総括・担当者のチャットがまだ同じプロジェクトにある必要があります。
2. **メニュー → バックアップを読み込む → ZIPファイルを選択**で16 MiB以下のZIPを選びます。大きいZIPは **ローカルパスから読み込む** を開き、最大128 MiBの絶対ローカルパスを入力します。
3. 名前、担当者数、依頼・発言・画像・音声の件数、復元できない理由がないか確認します。ここまでは元の会議記録を変更しません。
4. **確認した会議室を復元**を押します。既存の会議室・記録を上書き・統合しません。他のプロジェクトへは復元できません。
5. 上部で復元した会議室を選び、担当者と記録を確認します。新規依頼は一時停止した状態です。必要なら **新規依頼を再開** を押します。

未完了の依頼・作業が残るバックアップは、作業を勝手に再実行しないため会議室への復元を拒否します。ZIPの `index.html` で内容を閲覧し、作業を整理して新しいバックアップを作ってください。壊れたファイル、欠落した添付、参加者の所属を確認できない場合も復元しません。

読み込み中に閉じた場合は、**以前の復元準備を確認 → 続けて確認**を選びます。アップロード途中なら同じZIPを選び直します。結果が不明な場合は同じ復元の確認ボタンを使い、自動再試行はしません。別の新しい記録が見つかったら上書きせず停止します。

バックアップは会議記録用です。作業フォルダーの許可、作業用ファイル自体、QAの制御台帳、使用量ソース、実際のCodexチャットは取り込みません。現在のローカル制御・使用量記録は変更しません。別環境で作業を続ける前には、総括が作業フォルダーと検証環境を改めて確認します。欠けた使用量は推測で補いません。

## 8. 言語と使用量

**メニュー → 表示言語 / Language**で韓国語・English・日本語・简体中文・繁體中文を選べます。自動はブラウザーの言語を使います。中国語は明示的なHans/Hantを優先し、指定がなければTW/HK/MOは繁体字、その他の中国語設定は簡体字、それ以外の未対応言語は英語です。位置情報は取得しません。

メニューを切り替えても既存の発言、添付の説明、入力中の文章、モデル、保存済みのチーム設定は翻訳・変更しません。報告はユーザーが指定した、または元のプロジェクトで使っていた言語に従います。

待機中・表示・言語切り替え・点検・バックアップ・読み込みでは、プラグインが追加のAIを呼び出しません。実際の作業と新しいチームの初期設定には通常の使用量が発生します。説明書をモデルに読ませる場合も通常の文脈使用量があるため、必要な箇所だけを参照します。完了後の担当者別使用量は観測された記録から表示し、未取得・重複した使用量を推測しません。

## 困ったとき

| 状態 | 確認すること |
| --- | --- |
| 会議室が自動選択されない | 元のプロジェクト内のチャットか、チーム接続済みか確認。複数候補・未対応のホストでは直接選択。 |
| チーム作成が拒否された | 元のチャットに準備済みの依頼文を直接送信。権限や未対応モデルを迂回せず、元の試行を確認。 |
| 担当者が追加一覧にいない | 同じプロジェクト所属・保管状態を確認し、一覧更新。別プロジェクトの全チャットは列挙しない。 |
| 送信結果が不明 | 依頼IDと総括チャットで実際の結果を確認。自動再送せず、同じ内容を連続送信しない。 |
| ZIPの復元が拒否された | 元のプロジェクト・既存記録との競合・未完了作業・添付の破損を確認。詳細を開いて原因を読む。 |

データは `~/.codex/team-room` または `TEAM_ROOM_HOME` にあり、ソースフォルダーとは別です。実際の接続情報、会議記録、ZIP、個人のスクリーンショットを公開リポジトリへ載せないでください。
