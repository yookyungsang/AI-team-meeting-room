# 팀 회의실 사용 설명서

[English](USER_GUIDE.en.md) | **한국어**

**처음 설치하셨나요? [설치 후 작업자 팀 만들기](SETUP.ko.md)에서 프로젝트 선택 → 새 작업자 6명 생성 → 모델 선택 → 회의실 연결 → 첫 작업 지시까지 따라 하세요.** 이 문서는 이후의 일상 사용과 기능별 참고 설명서입니다.

팀 회의실은 프로젝트의 기존 총괄 채팅과 담당자 채팅을 연결해 요청, 질문, 진행 보고와 결과를 한곳에서 보는 플러그인입니다. 사용자는 총괄에게 목표를 전달하고, 필요한 담당자가 자신의 작업 결과를 직접 게시합니다.

이 설명서는 0.9.0 기준입니다. 다른 프로젝트에서도 사용할 수 있으며, 각 프로젝트의 담당자와 기록은 따로 관리합니다.

## 처음 사용하기

1. 해당 프로젝트의 기존 총괄 채팅을 엽니다.
2. **“이 프로젝트와 기존 담당자 채팅들을 팀 회의실에 연결해 줘”**라고 요청합니다. 연결할 담당자와 역할, 허용할 협업 범위를 함께 알려 주세요.
3. 연결이 끝나면 **“팀 회의실 열어 줘”**라고 요청합니다.
4. 회의실 상단에서 원하는 프로젝트가 선택됐는지 확인합니다.
5. 하단 입력창에 목표나 질문을 적고 **Enter**로 보냅니다.

일반 작업 중 부족한 담당자를 임의로 만들지는 않습니다. 새 대화창으로 팀을 만들고 싶다면 아래처럼 명시적으로 요청합니다. 연결 대상이 불명확하면 총괄이 확인합니다.

## 새 대화창으로 팀 만들기

원하는 Codex 프로젝트에서 **“이 프로젝트에 총괄·기획자·디자이너·프로그래머 2명·QA를 새 대화창으로 만들고 회의실에 연결해 줘. 역할별 모델도 고르게 해 줘”**라고 요청합니다. 프로젝트, 여섯 역할의 이름과 사용할 모델·추론 수준을 표로 확인한 뒤 선택합니다. **“전부 내 기본 모델을 유지해 줘”**라고 지정할 수도 있습니다. 선택이 이미 구체적이면 같은 내용을 다시 확인하지 않습니다.

확정하면 Codex의 실제 대화창 생성 도구로 필요한 채팅을 만들고 제목·역할 지침·회의실 연결을 진행합니다. 기존 회의실에 추가할 때는 현재 총괄과 이미 연결된 담당자를 유지하고 빠진 역할만 만듭니다. 프로그래머 두 명은 별도 대화창이며, 기본 분담은 핵심 로직·데이터와 화면·상호작용입니다. 실제 파일 분담은 총괄이 정합니다. 새 채팅에는 역할만 설정하고 구현 작업은 이후 실제 배정에서 시작합니다.

모델 추천은 실제 호스트에서 확인한 선택지 안에서 제공합니다. 총괄·기획·개발·QA는 균형형 모델, 디자이너는 시각 작업에 맞는 모델을 먼저 제안하며 추천을 자동 적용하지 않습니다. 예를 들어 현재 지원될 때 Sol은 지속적인 종합 작업, Terra는 문서·시각 자료, Astra는 가장 어려운 판단, Luna는 범위가 명확한 반복 작업의 후보입니다. 역할별 추천은 [공식 OpenAI 모델 안내](https://learn.chatgpt.com/docs/models)를 참고해 정한 플러그인의 안내이며 작업 품질이나 절감률을 보장하지 않습니다. 사용자가 고른 정확한 모델·추론 설정으로 새 채팅을 생성하고 기존 채팅 모델은 바꾸지 않습니다.

이 기능은 대화로 사용하는 구성 절차입니다. 별도의 생성 버튼이나 백그라운드 AI가 실행하는 방식이 아니며, 대화창 생성 도구를 지원하는 호스트가 필요합니다. 생성 중 끊겨도 진행 기록에서 이어가고 전달 여부가 불확실하면 새 채팅을 반복 생성하지 않습니다. 실제 생성되지 않았다는 확인과 사용자의 명시적 재시도 요청이 있을 때만 다시 시도합니다. 처음 역할을 설정하는 대화에는 정상 사용량이 생기며, 이후 정기 AI 확인은 추가하지 않습니다.

## 담당자 구성 바꾸기

**메뉴 → 팀과 회의 제어 → 구성원 편집**에서 직접 관리합니다.

1. 기존 담당자를 선택하고 **추가**를 누릅니다. 목록에 없는 채팅은 **목록에 없는 기존 채팅 찾기**로 총괄에게 한 번 준비를 요청한 뒤 **목록 새로고침**으로 불러옵니다. 새 채팅을 만드는 버튼은 아닙니다.
2. 뺄 사람은 **제외**를 누르고 이름을 확인합니다. 역할은 **기획자·디자이너·프로그래머·QA·효과음 담당자·직접 입력** 중 고릅니다. 총괄은 고정입니다. 프로그래머 두 명은 같은 역할과 다른 이름으로 구분합니다.
3. 선택을 확인하고 **변경 저장**을 누릅니다. 저장 전에는 적용되지 않습니다. 편집 닫기나 프로젝트 전환은 저장하지 않은 편집을 닫습니다. 이미 보낸 저장은 완료될 수 있습니다.

목록 읽기·선택·추가·제외·저장은 AI를 호출하지 않습니다. 기존 채팅 찾기 버튼만 총괄에게 목록 준비 요청을 보냅니다. 프로젝트가 불명확하면 총괄이 확인할 내용을 알려 줍니다. 지침과 실제 준비 작업에는 일반 사용량이 있으며 정기 AI 조회는 없습니다. 총괄에게 대화로 구성 변경을 요청하는 기존 방법도 사용할 수 있습니다.

기본 역할은 **공통 지침＋역할별 전문 지침**, 직접 입력은 **공통 기본 지침＋실제 배정 조건**을 연결합니다. 직접 입력을 고르면 명칭 입력칸이 나옵니다. 새 배정에서 짧은 지침 참조를 전달하며 공통은 한 번, 전문은 필요한 부분만 읽습니다. 역할 저장을 알리려고 작업자를 따로 호출하지 않습니다. [지침 연결표](skills/team-room/references/role-guidance.md)를 참고하세요.

다른 편집과 충돌하면 초안을 유지한 채 오류를 보여 줍니다. 목록 새로고침 후 다시 선택하세요. 저장 결과가 불확실하면 자동으로 다시 보내지 않으며 **같은 변경 다시 저장**은 원래 변경 번호와 내용을 유지합니다. 기존 대화 기록은 바꾸지 않습니다.

진행 중인 작업, 답변이 남은 질문, 파일·Editor 소유권이나 실행 중인 검증이 있으면 해당 담당자를 바로 제외하거나 역할 종류를 바꿀 수 없습니다. 먼저 완료하거나 중단을 확인하고 다른 담당자에게 명시적으로 인계해야 합니다. 제외해도 과거 발언과 이미 가져온 사용량 기록은 남고, 같은 채팅으로 다시 참여할 수 있습니다. 제외된 채팅의 새 사용량은 가져오지 않으며, 늦게 기록돼 아직 가져오지 못한 수치는 측정 불가로 남을 수 있습니다.

기존 담당자 ID를 다른 채팅에 재사용하지 않습니다. 다른 작업자 채팅으로 교체할 때는 새 담당자 ID를 사용합니다. 총괄 채팅의 주소는 유지하며 총괄 채팅을 바꾸려면 별도 회의실이 필요합니다. 표시 이름·직접 입력한 명칭은 회의실에 적용하고 선택한 역할 종류는 다음 새 배정의 지침에 연결합니다. 예전 배정의 역할은 보존하며 Codex 채팅 제목·모델·시스템 프롬프트는 자동 변경하지 않습니다. 구성 변경 자체는 AI 호출이나 담당자 메시지를 만들지 않지만, 총괄에게 변경을 요청하고 처리하는 대화에는 일반 사용량이 있습니다.

## 설치와 업데이트

Node.js 22 이상, Git, 로컬 플러그인과 MCP Apps를 지원하는 Codex가 필요합니다. 처음 설치할 때는 터미널에서 다음 명령을 실행합니다.

```sh
git clone https://github.com/yookyungsang/AI-team-meeting-room.git
cd AI-team-meeting-room
codex plugin marketplace add .
codex plugin add jyfood-room@jyfood-local
```

저장소가 비공개라면 GitHub 접근 권한이 필요합니다. 표시 이름은 **팀 회의실**, 내부 설치 ID는 `jyfood-room@jyfood-local`, MCP 서버 이름은 `team-room`입니다.

업데이트할 때는 원본 저장소에서 변경 사항을 받은 뒤 같은 설치 명령으로 반영합니다. 설치 캐시 파일을 직접 수정하지 않습니다.

```sh
git pull --ff-only
codex plugin add jyfood-room@jyfood-local
```

진행 중인 작업을 마친 뒤 Codex를 완전히 종료하고 다시 실행하면 새 설치본을 로드합니다. 코드 수정본을 로컬에서 설치한 경우에는 해당 원본 저장소를 기준으로 업데이트합니다.

## 요청 작성하기

원하는 결과와 지켜야 할 조건을 함께 적으면 총괄이 작업 범위와 완료 기준을 정하기 쉽습니다.

> 설정 화면의 글자가 읽기 어렵습니다. 기존 기능은 유지하면서 글자 크기와 간격을 조정하고, 관련 검증 후 최종 화면도 보여 주세요.

| 입력 | 동작 |
| --- | --- |
| Enter | 총괄에게 전송 |
| Shift+Enter | 입력 중 줄바꿈 |
| 한국어 조합 중 Enter | 글자 조합을 마치며 바로 전송하지 않음 |

사용자 요청은 선택한 프로젝트의 총괄에게 전달됩니다. 담당자에게 작업을 나누고, 결과를 통합하는 일은 총괄이 맡습니다.

직접 쓴 내용은 앞뒤 공백과 줄바꿈까지 그대로 저장·전달합니다. 새 요청의 자동 안내에는 프로젝트·요청 표식, 총괄 확인·한 번 전달 안내와 필요한 추가 지시 연결만 남깁니다. 총괄의 정확한 연결과 협업 규칙은 기존 조회·지침으로 확인합니다. 과거 기록은 바꾸지 않으며, 예전 요청의 저장 재시도는 원래 안내 형식을 유지합니다. 안내 축약에 별도 AI 호출은 없습니다.

회의실에서 프로젝트를 바꾸면 표시할 기록과 초안이 바뀝니다. Codex의 현재 채팅 자체가 다른 총괄 채팅으로 이동하지는 않으므로, 해당 프로젝트의 총괄 채팅에서 회의실을 여는 것이 좋습니다.

## 작업 중 내용 추가하기

총괄이 작업 중이어도 추가 조건이나 수정 의견을 보낼 수 있습니다.

> 방금 요청한 화면은 휴대폰에서도 읽기 편하게 해 주세요. 기존 버튼의 동작은 유지해 주세요.

추가 메시지는 가장 최근의 진행 중인 원래 요청에 연결됩니다. 총괄은 중간 판단과 완료 전에 추가 내용을 확인하고 기존 작업에 반영하도록 되어 있습니다. 추가 조건만으로 원래 작업을 다시 시작하거나 같은 업무를 중복 배정하지 않습니다.

메시지가 현재 작업에 반영될지 다음 순서로 대기할지는 Codex의 후속 메시지 처리 방식에 따릅니다. 전송 직후 실행 중인 도구가 즉시 중단되는 것은 보장하지 않습니다. 원래 요청이 이미 끝났다면 새 요청으로 보냅니다.

## 메뉴에서 확인하기

평소 화면에는 회의 대화와 입력창이 보입니다. 상단 **메뉴**를 열면 다음 정보를 확인할 수 있습니다.

| 메뉴 항목 | 확인할 내용 |
| --- | --- |
| 전송 상태와 입력 안내 | 연결 상태, 보낸 글 미리보기, 요청 ID, 전달 확인, 입력 키 안내 |
| 팀과 회의 제어 | 연결된 담당자와 역할, 새 요청 일시정지와 재개 |
| 요청 처리 기록 | 사용자 요청, 받는 사람, 처리 상태와 작업 진행 상태 |
| 작업 보호와 검증 | 파일·Editor 소유권, 인계 기록, 검증 통과·실패·차단 상태 |
| 완료 작업의 담당자별 사용량 | 완료된 작업의 담당자별 측정치와 합계, 누락·지연 등 측정 한계 |
| 사용 방법과 사용량 안내 | 전달 방식, 추가 메시지, 이미지와 사용량 설명 |

전송에 확인이 필요한 문제가 생기면 메뉴 버튼에 **전송 확인 필요**가 표시됩니다. 메뉴는 닫기 버튼이나 Escape로 닫을 수 있습니다.

## 전송 상태 이해하기

| 표시 | 의미와 확인 방법 |
| --- | --- |
| 기록 저장 중 | 사용자 요청을 저장하는 중입니다. |
| 저장됨 · 호스트 전송 확인 대기 | 내용은 저장됐고 Codex 채팅으로 전달됐는지 확인 중입니다. |
| 호스트 전달 확인 | Codex가 메시지 전송을 접수했습니다. 작업 완료는 회의실의 실제 결과로 확인합니다. |
| 처리 여부 확인 필요 | 응답이 늦거나 불확실합니다. 메뉴의 요청 ID로 총괄 채팅에서 확인합니다. |
| 전송 거절 | 전달이 거절됐습니다. 처리 여부와 원인을 확인한 뒤 필요한 조치를 결정합니다. |

실패하거나 확인이 늦어진 메시지를 자동 재전송하지 않습니다. 확인 대기 중 같은 본문을 반복 전송하는 것도 막습니다. 다른 추가 내용은 계속 입력할 수 있습니다. 전달 확인이 늦게 도착해도 작성 중인 다음 초안은 유지합니다.

## 작업 이미지 보기

작업자가 진행 보고나 최종 보고에 첨부한 시안, 생성 이미지, 스크린샷을 회의 대화 안에서 볼 수 있습니다. 이미지를 누르면 크게 보이며, 닫기 또는 Escape로 돌아옵니다.

- **작업 중:** 직접 요청했거나 디자인 선택·오류 확인 등 이미지가 꼭 필요한 때만 대표 이미지 1장을 우선 보여 줍니다.
- **완료 시:** 이미지·화면·UI·디자인·3D 결과를 만든 담당자가 자신의 회의실 완료 보고에 실제 최종 상태의 대표 이미지 1장을 반드시 직접 첨부합니다. 중간에 보여 줬더라도 최종 보고에 포함합니다.

생성한 최종 이미지나 최종 상태를 정확히 보여 주는 기존 이미지는 재사용합니다. 없다면 허용된 작업 범위에서 최종 화면을 한 번 캡처합니다. 총괄은 이미지 작업 배정에 완료 이미지 필수 조건을 지정하며, 지정한 작업은 해당 담당자의 최종 첨부 없이는 완료 처리되지 않습니다. 생성·캡처·파일 접근이 불가능하면 차단 사유를 알리고 성공 완료로 표시하지 않습니다. 중간 시안을 완성 결과로 표시하지 않으며, 글이나 비시각적 작업에는 장식용 이미지를 만들지 않습니다.

이미지는 만든 담당자가 보고에 첨부해야 합니다. 다른 채팅에 있는 이미지가 자동으로 복사되는 것은 아닙니다. 총괄은 이미 올라온 이미지를 중복 게시하거나 이미지 알림만을 위해 담당자를 따로 호출하지 않습니다. 지원 형식은 PNG, JPEG, GIF, WebP이며 한 발언에 최대 4개, 파일당 8 MiB입니다. 파일은 회의실 서버가 실행되는 컴퓨터에서 읽을 수 있어야 합니다. 게시한 사본은 원래 작업 파일이 바뀌거나 없어져도 유지됩니다.

이미지를 불러오지 못하면 **다시 보기**를 누를 수 있습니다. 원격 파일 주소나 다른 컴퓨터의 경로만 전달한 경우에는 작업자가 서버에서 읽을 수 있는 이미지 파일을 준비해야 합니다.

## 공통 협업 지침

[협업 지침 전문](skills/team-room/references/collaboration-policy.md)은 플러그인에 포함돼 있으며 회의실을 사용하는 각 프로젝트의 운영 기준입니다.

- 총괄 운영 12개 항목과 프로그래머 협업 9개 절을 따릅니다. 연결된 프로그래머가 둘 이상이면 독립적인 작업의 병렬 처리를 우선합니다.
- 같은 파일의 동시 편집과 같은 공유 앱의 동시 조작은 피하고, 필요한 소유권과 조작권을 인계합니다.
- 프로그래머는 같은 오류에 같은 방법으로 최대 1회 재시도합니다. QA도 원인 분석 뒤 최대 1회만 재시도하며 환경 차단이나 동일 오류 반복 시 중단하고 총괄에게 보고합니다.
- 개발자 자체 점검 뒤 독립 QA에 인계하고, 총괄은 실제 결과와 필요한 검증 근거로 완료 여부를 판단합니다. QA가 없거나 검증할 수 없으면 그 한계를 밝힙니다.
- 중복 업무, 반복 분석, 불필요한 상태 확인과 보고를 줄입니다. 작업이나 필수 검증을 생략하라는 뜻은 아닙니다.

실제 연결된 담당자와 사용자가 승인한 범위에서 적용합니다. 각 프로젝트의 사용자 지정 역할·보존 규칙과 호스트/도구 제한을 우선합니다. 모델 선택 지침은 도구와 승인 범위가 허용할 때 적용하며, 플러그인이 대화의 모델을 자동으로 바꾸지는 않습니다.

## QA 재검증 지시하기

총괄에게 **“수정된 사례와 영향 범위만 QA에게 재검증시키고, 필요한 재개 승인 기록도 지시와 함께 처리해 줘”**라고 요청하세요. 총괄은 기존 작업 턴에서 `room_validation`의 `retest`로 수정 근거·검증 범위·기존 담당자를 지정합니다. 플러그인은 재개 승인을 먼저 기록한 뒤 같은 호출에서 회의실 지시를 저장하며, QA가 쓸 새 실행 키도 함께 준비합니다. QA가 스스로 차단을 풀 필요가 없습니다.

새로 검사를 실제 실행할 때는 새 키를 쓰고, 응답을 못 받아 같은 호출의 저장을 다시 확인할 때만 원래 키와 내용을 유지합니다. 예전 키를 복구해야 새 검사를 할 수 있는 구조가 아닙니다. 과거 실패는 보존하고 재시도 한도와 총괄 권한도 유지합니다.

실행 중인 검증은 먼저 상태를 확인해야 하며, 끝난 요청·완료한 담당자 작업을 자동으로 재시작하지 않습니다. 실제 재검증은 진행 중 요청에 배정된 기존 담당자가 수행합니다. 재개 승인만으로 검사·에디터 실행·메시지 전송이 자동 발생하지 않습니다. 별도 승인 확인 AI나 정기 호출 없이 처리하며 지침·도구 사용에는 일반 문맥 사용량이 있습니다. [상세 절차](skills/team-room/references/work-controls.md#retest-directives-and-execution-keys)를 참고하세요.

## 디자이너에게 작업 요청하기

회의실에서 **“기존 규격을 확인하고 대표 시안부터 검토해 줘. 수정사항은 모아서 반영하고 개발 담당자에게 파일·연결 사양을 넘겨 줘. 최종 이미지는 제작자가 직접 첨부하고 실제 적용·QA 여부도 구분해 줘”**라고 요청할 수 있습니다. 이미 확정한 규격·스타일·유지할 요소가 있으면 함께 알려 주세요.

[디자이너 전용 상세 규칙](skills/team-room/references/design-collaboration.md)은 제작 전 규격 확인 → 시안 검토 → 수정·버전 보존 → 개발자 인계 → 자체 점검·독립 QA를 설명합니다. 2D·UI·3D 중 해당하는 항목만 적용하고, 필요한 누락·충돌만 질문합니다. 매번 여러 시안·승인 회의를 만들거나 규칙 공지 때문에 전원을 호출하지 않습니다.

제작 완료, 앱·게임 연결 완료, 실제 화면 검증 완료는 구분합니다. 중간 이미지는 필요한 때만, 최종 이미지는 만든 담당자가 자신의 완료 보고에 직접 첨부합니다. 이 절차는 협업 지침이며 자동 품질 인증 기능이 아닙니다. 별도 검토 AI·정기 호출은 없고 지침과 원래 작업에는 일반 사용량이 있습니다.

## 보고 언어와 게시 전 점검

보고는 **사용자가 지정한 출력 언어**를 우선하고, 별도 지정이 없으면 **해당 프로젝트·원래 요청에서 사용자가 계속 쓰던 언어**를 따릅니다. 한국어로 고정하지 않습니다. 다른 언어의 문서나 로그를 붙여 넣어도 그 인용문만 보고 전체 보고 언어를 바꾸지 않습니다. 사용자가 명시적으로 언어를 바꿔 달라고 하면 그 지시를 따릅니다.

작성자는 게시 직전에 원래 보고 작성 턴에서 일반 설명·질문·답변에 의도하지 않은 언어 혼입이 없는지 한 번 확인하고 바로잡습니다. 코드·파일명·정확한 원문 근거와 사용자가 쓴 내용은 그대로 유지합니다. 총괄은 다음 필요한 업무 배정에 보고 언어를 짧게 안내하며 이를 위해 작업자를 따로 호출하지 않습니다.

별도 번역 AI·언어 탐지 서비스·자동 재작성은 추가하지 않습니다. 작성자의 자체 점검 규칙이며 서버가 언어를 강제 판정하는 기능은 아닙니다. 기존 글은 자동 수정·재게시하지 않고, 이 규칙이 화면 메뉴의 언어를 자동으로 바꾸지도 않습니다. 지침과 원래 작성 과정에는 일반 문맥 사용량이 발생합니다. [상세 규칙](skills/team-room/references/report-language.md)을 참고하세요.

## 사용량 이해하기

새 보고는 코딩 지식 없이도 이해하도록 **완성한 것 → 아직 확인할 것 → 다음 할 일** 순서로 자연스럽게 설명합니다. 예를 들어 "approval 보존" 대신 "이미 승인받은 내용은 그대로 유지했어요"라고 씁니다. 파일명·검사 기록·설정은 같은 게시물의 **작업 상세 보기** 안에 남기며 필요할 때 펼칠 수 있습니다. 상세를 펼쳐도 도구나 AI를 추가 호출하지 않습니다. 담당자 조회에는 쉬운 설명과 기술 상세가 모두 그대로 제공됩니다.

담당자끼리도 "작은 화면에서 설명이 잘려요. 두 줄로 나눠도 될까요?"에 "네. 두 줄로 나눠 주세요. 버튼 크기는 유지해 주세요"처럼 필요한 문제를 자연스럽게 묻고 답하도록 지침에 반영했습니다. 전달 방식·작업 범위·필수 검증은 유지하며, 실패·미검증·사용자 승인 필요는 쉬운 본문에도 알립니다. 대화를 꾸미려고 질문이나 인사·감사만 반복하지 않습니다.

이 표시는 작성자가 처음부터 쉬운 `text`와 필요한 `details`를 함께 남기는 방식입니다. 기존 글을 자동 번역하거나 재작성하지 않으며, 내용 전체가 예전처럼 `text`에만 있는 글은 그대로 보입니다. 별도 요약 모델은 호출하지 않습니다. 보고 작성과 지침·도구 설명·조회 본문에는 정상 사용량이 발생하므로 기존과 토큰 수가 정확히 같다고 보장하지는 않습니다.

회의실 화면의 기록 조회·갱신, 이미지 표시·확대 자체는 별도 AI 호출을 하지 않습니다. 이미지 바이트도 모델이 읽는 회의 기록에 넣지 않습니다.

요청을 받아 총괄과 담당자가 실제로 작업하거나, 이미지를 생성·분석하거나, 진행 보고를 작성하면 정상적인 AI 사용량이 발생합니다. 모델이 읽는 지침·도구 설명·첨부 설명·도구 결과도 문맥 사용량에 영향을 줄 수 있습니다. 전체 사용량이 0이거나 일정 비율 절감된다고 보장하는 기능은 아닙니다.

사용량을 줄이려면 요청 범위를 명확히 하고, 필요한 담당자만 참여시키며, 중간 이미지와 같은 내용을 반복 보고하지 않는 것이 좋습니다. 완료 결과와 필요한 검증은 유지합니다.

## 파일 보호·복구·자동 검증

총괄에게 **“허용된 작업 폴더에 파일 보호와 검증 기능을 설정해 줘”**라고 요청하면 해당 프로젝트의 작업 폴더를 한 번 설정합니다. Unity 검증을 사용한다면 공식 Unity CLI 실행 파일과 호환 Editor·라이선스·테스트 환경도 필요합니다. 이 설정은 새 파일 접근이나 빌드 권한을 자동으로 부여하지 않습니다.

- **파일 보호:** 담당자가 편집할 파일을 묶어 예약합니다. 다른 담당자의 중복 예약과 오래된 내용으로 덮어쓰는 저장을 거절합니다. 편집은 보호된 저장 도구를 사용하고, 씬·공유 Editor는 한 명에게 조작권을 인계합니다. 일반 편집기의 직접 저장까지 막는 운영체제 잠금은 아닙니다.
- **재시도 제한:** QA는 검증 시작·결과를 기록합니다. 첫 실패 뒤 원인 분석을 거쳐 최대 한 번만 재시도하고, 반복 오류나 환경 차단은 총괄이 조치·재개를 기록하기 전까지 다음 실행을 막습니다. 외부 명령을 직접 실행해 이 제한을 우회하지 않습니다.
- **작업 복구:** 필요한 인계 시점에 현재 결과·다음 작업·변경 파일을 저장합니다. 중단이 확인되면 총괄이 기존 담당자에게 인계하며 기록과 파일을 보존합니다. 시간 경과만으로 중단을 추측하거나 자동 재전송하지 않고, 저장하지 않은 편집기 내용은 복원할 수 없습니다.
- **Unity 검증:** 컴파일, EditMode·PlayMode 테스트, 빌드를 한 번 실행하고 종료 코드·오류 로그·테스트 XML·새 산출물을 확인합니다. 이미 열린 Editor나 불충분한 증거는 차단·미검증으로 표시합니다. 실제 기기 플레이와 화면 확인은 별도 검증입니다.

## 음원 첨부와 미리듣기

회의실 입력창에서 **“효과음 담당자가 최종 음원을 자신의 완료 보고에 첨부해 줘. 게임 연결과 실제 청취 검증 여부도 구분해 줘”**라고 요청합니다. 실제 음원을 가진 담당자가 서버에서 읽을 수 있는 파일을 첨부합니다. 사용자가 파일 경로를 글로 적기만 하거나 다른 채팅에 올린 음원은 자동 첨부되지 않습니다.

본문 아래의 **▶ 음원 미리듣기**를 누르면 해당 파일을 불러와 창을 엽니다. **창 안의 재생 버튼**을 눌러 듣고 일시정지·이동·음량을 조절할 수 있습니다. 음원은 작업 상세 밖에 표시되며 자동 재생하지 않습니다. 닫기·Escape·프로젝트 전환·화면 숨김·종료 시 재생을 정리하고, 일반 보고 갱신 중에는 열린 플레이어를 유지합니다.

WAV·MP3·OGG를 한 발언에 최대 3개, 파일당 8 MiB까지 첨부할 수 있습니다. 첨부 때 사본을 보관하므로 원본이 바뀌거나 없어져도 게시한 버전은 유지합니다. 실제 코덱이나 호스트 정책으로 재생이 제한되면 그 한계를 표시하며 정상 청취로 처리하지 않습니다.

미리듣기는 눌렀을 때만 UI 전용 도구로 파일을 읽고, 같은 파일은 화면 캐시를 재사용합니다. 재생·일시정지·이동·음량 조절에 AI 호출이나 전사는 없습니다. 모델에는 작은 첨부 정보만 전달하고 음원 바이트와 base64는 일반 모델 문맥에 넣지 않습니다. 지침과 첨부 설명에는 일반 문맥 사용량이 있어 전체 사용량이 기존과 정확히 같다는 뜻은 아닙니다.

효과음 담당자는 제작, 프로그래머는 게임 연결, QA는 실제 재생을 검증합니다. [효과음 협업 규칙](skills/team-room/references/sound-collaboration.md)에 따라 제작자의 최종 첨부 조건을 지정하며 음원 제작·게임 연결·청취 검증의 완료를 구분합니다. 재생 버튼이 보이거나 파일 검사를 통과한 것만으로 실제로 듣거나 게임을 검증했다고 보고하지 않습니다.

## 완료 후 담당자별 사용량

총괄이 연결된 기존 대화의 로컬 사용량 기록을 한 번 연결하면, 작업 완료 결과 아래와 메뉴에 담당자별 입력·출력 토큰과 측정 가능한 합계가 표시됩니다. 추가 요약 AI를 호출하거나 작업 중 정기 사용량 보고를 보내지 않습니다. 현재 턴의 기록이 늦으면 같은 표시가 나중에 갱신됩니다.

채팅 전체의 과거 누적을 해당 작업의 사용량으로 표시하지 않습니다. 로컬 기록이 없거나 읽을 수 없으면 **측정 불가**, 마지막 턴의 기록이 아직 끝나지 않았으면 **일부 기록**, 다른 작업과 겹쳐 분리할 수 없으면 그 한계를 표시합니다. 누락된 담당자를 0으로 계산하지 않습니다. 회의·대기·반복 검증이 같은 턴에 섞인 토큰을 임의로 쪼개지 않습니다.

캐시 입력은 입력 토큰에, 추론은 출력 토큰에 이미 포함됩니다. 표시는 로컬에서 관찰한 사용량이며 계정 청구서 전체와 같다고 보장하지 않습니다. 새 도구 설명과 지침, 일반 작업·보고에는 정상적인 문맥 사용량이 발생합니다.

실제 한도 기록이 있으면 **계정 한도 사용률(%)과 남은 비율**도 함께 표시합니다. 같은 집계 기간의 작업 전후 기록이 모두 있으면 증가분을 `%p`로 보여 줍니다. 계정 전체 수치라 다른 채팅의 사용도 포함될 수 있으며 담당자별로 나누지는 않습니다. 기간 초기화·기록 누락 시 변화량은 확인 불가로 표시하고, 토큰 수를 %로 환산하지 않습니다. 기존 로컬 기록을 우선 사용하고, 필요할 때만 총괄의 기존 완료 턴에서 공식 사용량을 한 번 조회합니다.

## 일시정지하기

메뉴의 **새 요청 일시정지**는 해당 프로젝트의 새로운 사용자 요청과 새 전달·배정을 막습니다. 이미 실행 중인 Codex 작업을 취소하지 않습니다. 진행 중인 작업을 멈추려면 해당 Codex 채팅의 중지 기능을 사용해야 합니다.

진행 중인 작업의 답변과 마무리 기록은 남길 수 있습니다. 다시 새 요청을 받으려면 메뉴에서 재개합니다.

## 화면이 겹치거나 분할됐을 때

회의실과 총괄 채팅이 좌우로 나뉘어 보이면 Codex의 분할 보기 상태입니다. 회의실 쪽을 선택하고 앱 상단의 전체 보기 버튼을 사용합니다. Windows 기본 단축키는 **Ctrl+Shift+F**이며 사용자 설정에 따라 다를 수 있습니다. [공식 단축키 안내](https://learn.chatgpt.com/docs/reference/commands)를 참고하세요.

전체 보기 위에 떠 있는 총괄 입력창은 Codex의 기본 입력창입니다. 회의실 내부 입력칸과는 별개이며, 위치 저장과 자동 접기 여부는 Codex가 관리합니다. 창의 접기 버튼을 사용하거나 앱의 보기 배치를 바꿔 사용합니다. 회의실 플러그인에는 그 입력창의 좌표 고정이나 완료 후 자동 접기를 제어하는 공개 기능이 연결돼 있지 않습니다.

## 문제 해결

| 현상 | 먼저 확인할 내용 |
| --- | --- |
| 보낼 수 없음 | 프로젝트 선택, 연결 상태, 일시정지 여부, 빈 입력 또는 같은 본문의 전송 확인 대기 여부를 확인합니다. |
| 전달됐는데 답변이 없음 | 호스트 전달 확인은 작업 완료와 다릅니다. 총괄 채팅에서 진행·대기·차단 여부를 확인합니다. |
| 추가 지시가 바로 반영되지 않음 | Codex가 현재 작업 조정 또는 다음 순서 대기로 처리할 수 있습니다. 같은 내용을 자동·반복 재전송하지 않습니다. |
| 새 기능이 보이지 않음 | 원본에서 업데이트를 설치했는지 확인하고, 진행 중인 작업을 마친 뒤 Codex를 완전히 종료·재실행합니다. |
| 이미지가 보이지 않음 | 최신 설치본인지, 보고에 실제 첨부됐는지, 서버에서 파일을 읽을 수 있었는지 확인합니다. |
| 담당자 구성을 바꾸고 싶음 | 메뉴 → 팀과 회의 제어 → 구성원 편집에서 추가·제외·표시 변경 후 저장합니다. 같은 회의실에서 변경하며, 진행 중인 담당자는 완료나 명시적 인계 후 제외합니다. |

## 기록 보관

기본 저장 위치는 사용자 홈 아래 `~/.codex/team-room`입니다. `TEAM_ROOM_HOME`을 지정했다면 그 위치를 사용합니다.

| 파일 또는 폴더 | 보관 내용 |
| --- | --- |
| projects.json | 프로젝트와 기존 채팅 연결 설정 |
| team-setups.json | 새 작업자 팀의 구성 계획·모델 선택·생성 진행과 실제 채팅 연결 결과 |
| rooms 폴더의 프로젝트별 JSON 파일 | 요청, 발언, 상태와 이미지 첨부 정보 |
| 프로젝트 JSON 이름 뒤에 .images가 붙은 폴더 | 게시한 이미지 사본 |
| 프로젝트 JSON 이름 뒤에 .audio가 붙은 폴더 | 게시한 음원 사본 · 이미지 폴더와 함께 백업 |

원본 저장소나 플러그인을 업데이트해도 같은 데이터 위치를 사용하면 기록을 유지합니다. 기록을 백업할 때는 JSON과 이미지 폴더를 함께 보관합니다. 실제 연결 정보, 대화 기록, 사용자 스크린샷과 토큰을 소스 저장소에 올리지 않습니다.

자동 클라우드 동기화, 다른 채팅 전체 기록의 자동 수집, 독립적인 모델 실행 환경은 제공하지 않습니다.
