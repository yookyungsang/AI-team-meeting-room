# v0.16.1 · 저장 중단 예외 처리 보완

디스크 공간 부족 등으로 백업 준비나 첨부 저장이 중간에 실패했을 때, 같은 요청으로 이어가기가 막힐 수 있는 부분을 보완했습니다.

- 업로드가 일부만 저장됐다면, 사용자가 같은 백업을 다시 확인할 때 원래 데이터와 일치하는 부분만 인정하고 남은 부분을 이어 씁니다. 내용이 다르면 멈추며 기존 바이트를 잘라내거나 덮어쓰지 않습니다.
- 파일 경로로 준비하는 ZIP 사본과 복구하는 첨부는 임시 파일에 완전히 저장한 뒤 반영합니다. 저장에 실패하면 불완전한 ZIP이나 첨부를 완료된 파일로 남기지 않습니다.
- 예전 버전에서 중간에 남은 ZIP 사본도 선택한 원본과 앞부분이 정확히 같을 때만 다시 준비합니다. 중단된 복구를 미리 볼 때는 최초 확인한 ZIP의 검사값을 다시 확인합니다.
- 원본 ZIP·기존 회의 기록·다른 프로젝트는 유지합니다. 자동 재시도·반복 AI 점검·사용량 추정·담당자 호출은 추가하지 않았습니다. 사용자가 직접 같은 요청을 다시 확인할 때만 진행합니다.

## English

Fixes recovery after partial storage failures. Explicit upload retries verify the already-written prefix and append only the matching missing tail. Local-path ZIP staging and restored attachments publish complete temporary files atomically instead of leaving partial final files after write errors. A matching legacy partial ZIP can be reconciled without replacing different bytes. Resumed previews recheck the original archive checksum.

No source archive, existing room or other project is overwritten. No automatic retries, model calls, staff messages or background checks are added. The UI flow and tool schema remain unchanged. Existing safeguards for malformed/foreign backups, destination conflicts, interrupted registry commits, workspace authorization and late callbacks remain in force.

## Validation scope

`npm run check:package` and all 234 isolated regression tests passed, including four new storage-failure/archive-change cases.

Tests inject partial writes and simulated ENOSPC errors into upload, local ZIP staging and attachment storage, then verify explicit continuation, unchanged original records and rejection of mismatched bytes. A separate case changes a valid ZIP after an interrupted recovery and confirms that preview/apply refuse it. These are isolated synthetic filesystem checks, not tests performed by filling a real disk. The UI layout is unchanged from v0.16.0; its five-language browser results are not repeated as new native-host evidence. Actual Codex restart/duplicate-tab and complete native approval flows remain unverified.
