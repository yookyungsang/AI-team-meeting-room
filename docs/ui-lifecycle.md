# 화면 높이와 닫힘 처리 · 0.3.1

## 0.7.4 · QA 재개 승인과 재검증 지시의 통합 기록

총괄 전용 `room_validation(operation="retest")`가 선택한 canonical 사례·수정/환경 조치 근거·검증 범위·기존 배정 담당자를 받아 재개 승인을 먼저 영구 기록하고 같은 호출에서 회의실 지시를 저장합니다. 사례별 새 실행 키를 반환하며 새 실행과 같은 호출의 저장 재시도 안내를 구분합니다. 반복 호출은 승인·세대·키·게시물을 중복 생성하지 않고, 게시 후 응답 유실은 native 재전송을 허용하지 않습니다. 게시 전 실패는 같은 키로 복구하며 새 승인으로 대체된 미실행 키는 이후 세대에 사용할 수 없습니다.

기존 실패·명시적 총괄 권한·현재 배정·프로젝트 범위·실행 중 검증/Unity 차단·재시도 한도를 유지합니다. 새 검사를 실제 실행하기 전에는 이전 통과 기록으로 필수 재검증을 완료할 수 없습니다. 종료된 작업을 자동 재개하거나 새 작업자·AI·에디터 실행·소유권 획득·자동 전달·정기 검사를 추가하지 않습니다. 기존 턴에서 별도 승인/게시 호출과 키 복구 왕복을 줄이며 일반 문맥 사용량은 남습니다.

합성 프로젝트의 승인/지시·권한·일괄 실패·중복/변경 재시도·저장 중단 복구·과거 키·완료 차단·MCP 연결을 검증합니다. 기존 npm test와 문서·패키지 검사를 수행하며 실제 사용자 QA/Unity 실행이나 회의 기록 변경은 하지 않습니다. 레이아웃과 표시 전환은 변경하지 않습니다.

패키지의 design-collaboration.md에 제작 전 규격, 대표 시안 검토, 수정·버전 보존, 개발자 인계, 자체 점검·독립 QA와 최종 이미지 보고를 추가합니다. 기존 역할·파일/Editor 소유권·승인 범위·사용자 언어·최종 첨부·중단 복구 조건을 유지합니다. 프로젝트·엔진과 무관하게 해당 2D·UI·3D 항목만 적용하고 규격·피드백·후속 인계는 기존 자료와 변경분을 재사용합니다.

운영 스킬·공통 협업 지침·한국어/영어 README와 사용·설치 안내에서 연결합니다. 실제 디자인 배정 때 필요한 절만 읽고 충분한 지시에는 추가 회의를 생략합니다. 별도 검토·번역 모델·정기 호출·다중 시안 생성 의무·자동 품질 판정은 추가하지 않습니다. 지침과 실제 작업에는 일반 사용량이 있으며 절감률·무사용량을 보장하지 않습니다.

문서·메타데이터와 UI 초기화의 버전 표시만 변경합니다. 내용·참조 링크·전체 정책 보존·패키지 일치를 확인하며, 실행 로직·레이아웃·사용자 기록과 무관한 앱·게임 검증은 반복하지 않습니다.

## 0.7.2 · 사용자의 보고 언어 유지와 같은 턴의 게시 전 점검

보고 언어를 한국어에 고정하던 운영 스킬·도구 설명·새 역할 초기 지침을 수정합니다. 사용자의 명시적 출력 언어, 해당 프로젝트·원래 요청에서 계속 사용하던 언어를 따릅니다. 인용·로그·코드·지침·UI의 언어는 보고 언어 변경 지시가 아닙니다. 총괄은 다음 필요한 배정·변경분 인계에만 짧은 언어 안내를 포함합니다.

모든 담당자는 기존 보고 작성 턴에서 일반 설명의 언어 혼입을 한 번 점검하고 게시 전에 바로잡습니다. 원래 사용자 입력·정확한 코드와 근거·저장된 발언·재시도 본문은 보존합니다. 별도 번역·탐지 모델, 검토 턴·직원 호출·정기 검사·문자 기반 차단이나 UI 자동 번역은 추가하지 않습니다. 작성자 지침이므로 완전한 언어 판정·혼입 방지를 보장하지 않으며 지침·작성 과정에는 일반 문맥 사용량이 있습니다.

검증은 지침의 적용 범위·참조 링크·배포 패키지·기존 Node 검사로 수행합니다. 실제 모델을 별도로 호출해 언어 실험을 하거나 사용자 기록을 재작성하지 않습니다. 화면 레이아웃과 저장·전달 로직은 변경하지 않습니다.

## 0.7.1 · 효과음 협업과 사용자 선택 음원 미리듣기

공통 지침에 효과음 제작·개발 연결·독립 QA, 출처·재생 사양·실제 청취와 검증 한계, 초기 후보와 재시도 제한을 추가합니다. 음원 제작자의 `requireFinalAudio:true` 조건은 본인의 완료 `audio` 첨부를 검사하고 명시적 복구·기존 pending 담당자 인계에도 유지합니다. 기존 총괄 12개·프로그래머 9개·QA 8개 정책과 사용자 승인·파일/Editor 소유권·모델 선택 제한을 유지합니다.

`room_post`·`room_reply`는 WAV/MP3/OGG 파일을 3개, 각 8 MiB까지 첨부합니다. 입력·헤더·일괄 검사를 거쳐 내용 해시로 별도 `.audio` 폴더에 저장하고 메시지 JSON에는 작은 메타데이터만 보관합니다. 같은 게시 키·완료 답변의 첨부는 불변이며 원본 변경·삭제에도 원래 사본을 재생합니다. `room_audio`는 정확한 프로젝트·요청·발언·음원 ID로 조회하고 바이트는 모델용 content가 아닌 UI 전용 메타데이터로만 반환합니다.

음원 카드는 작업 상세 밖에 표시하고 눌렀을 때만 한 파일을 읽습니다. 기본 재생 창은 사용자 조작, 자동 재생 없음, 제한된 캐시를 사용합니다. 같은 프로젝트의 보고 갱신은 열린 플레이어와 재생 위치를 보존하고 닫기·Escape·숨김·프로젝트 전환·teardown은 정리하며 늦은 결과와 분리된 버튼은 다시 열지 못합니다. 새 AI·전사·음원 분석·정기 확인이나 외부 네트워크 권한은 추가하지 않습니다. 새 지침·첨부 설명에는 정상 문맥 사용량이 있습니다.

가상 음원·담당자를 사용하는 Node 검증과 1280px·420px Chromium 하네스로 형식·스냅샷·잘못된 범위·최종 조건·WAV 디코딩/재생 진행·캐시·갱신·종료 뒤 늦은 응답과 기존 레이아웃을 확인합니다. 하네스는 기기 출력에서 실제 소리를 듣거나 게임 안의 재생을 검증하지 않습니다. 실제 Codex 표시 전환·호스트 미디어 정책은 별도 확인이 필요합니다. 테스트 캡처와 합성 음원은 실제 사용자 자료가 아니며 저장소에 커밋하지 않습니다.

UI 전용 미디어·CSP는 [MCP Apps 규격](https://github.com/modelcontextprotocol/ext-apps/blob/main/specification/2026-01-26/apps.mdx)의 앱 전용 도구, 도구 응답 메타데이터와 기본 `media-src 'self' data:` 동작을 따릅니다.

## 0.6.0 · 새 팀 생성 절차와 역할별 모델 선택

`room_team`은 명시적인 새 대화창 팀 구성 요청에 사용하는 로컬 계획·진행 기록입니다. 기본 여섯 역할은 총괄·기획자·디자이너·프로그래머 2명·QA이며 현재 호스트에서 확인한 모델·추론 선택지를 제안합니다. 추천은 자동 적용하지 않고 사용자가 고른 설정만 native 생성 요청에 전달하며 기본 모델 선택은 model·thinking을 생략합니다. 기존 담당자와 총괄 채팅은 유지합니다.

계획·승인·생성 예약·실제 결과·제목 확인·연결을 분리해 중단 후 같은 시도를 재생성하지 않습니다. 불확실 결과는 실제 native 기록으로 대조하며, 미생성 확인과 명시적 사용자 재시도 요청 전에는 새 생성 예약을 허용하지 않습니다. 파일은 외부 `team-setups.json`에 저장하며 저장 응답은 간결하게 반환합니다. 서버가 대화창·AI·CLI 런타임을 실행하거나 자동 재시도·정기 호출하지 않습니다. 실제 생성과 초기 역할 턴에는 정상 사용량이 생깁니다.

가상 native 결과로 역할 수·모델 조합·기본값 유지, 중복 예약 방지, 중단 복구, 프로젝트·호스트·제목 확인, 기존 명단과 동시 변경·연결 직후 중단 및 지연 재시도를 검사합니다. 실제 사용자 채팅 여섯 개를 생성하는 검증은 하지 않습니다. 이 기능은 총괄 대화에서 쓰는 절차이며 위젯 레이아웃 변경은 없습니다.

## 0.5.0 · 같은 회의실의 담당자 구성 변경

총괄용 `room_members`는 사용자 요청에 따른 담당자 추가·제외·복귀와 회의실 표시 이름·역할 변경을 저장합니다. `room_state`의 현재 revision과 고정 changeId를 사용해 동시 변경과 저장 재시도를 검사합니다. 예전 변경의 늦은 재시도가 나중 구성을 되돌리지 않습니다. 모든 담당자 ID의 채팅·호스트는 제외 후에도 불변이며, 다른 채팅 교체는 새 담당자 ID를 사용하고 총괄 채팅 교체는 별도 회의실로 처리합니다.

대기·예약된 작업, 미답변 질문 양 끝의 담당자, 미반환 파일·Editor 소유권, 실행 중인 검증은 제외를 막습니다. 회의 기록과 작업 제어를 함께 잠근 상태에서 연결 설정만 저장하며, 기록과 제어 파일을 다시 쓰거나 없는 파일을 만들지 않습니다. 제외된 담당자는 과거 발언·완료 답변 재시도와 측정 사용량에서만 보존하고 새 배정·질문·인계·발언은 차단합니다. 역할·이름 변경 전의 보고는 작성 당시 정보를 유지합니다. 기존 버전 데이터는 조회만으로 이관하지 않습니다.

격리된 가상 자료로 수정·재시도·동시 프로세스 충돌, 작업 인계·이미지 조건 보존, 질문·소유권·검증 차단, 과거 기록과 사용량의 보존을 검사합니다. 메뉴는 기존 갱신으로 현재 담당자만 표시하고, 과거 발언의 이름·역할과 초안을 유지합니다. 레이아웃은 변경하지 않으며 실제 사용자 명단 수정이나 Codex 채팅 간 전달은 검증에서 실행하지 않습니다. 구성 저장은 새 AI 호출이나 자동 연락·재전송을 추가하지 않습니다.

## 0.4.3 · 자동 전달 안내 축약과 사용자 원문 보존

새 요청의 자동 안내에는 프로젝트·요청 표식, `room_get`으로 연결된 총괄 확인·한 번 전달 안내와 필요한 원래 요청 연결만 남깁니다. 반복 설명·표시 이름·채팅 ID·host는 생략하며, 기존의 필수 조회와 공유 지침으로 정확한 전달 대상과 협업 규칙을 확인합니다. 추가 지시의 중복 배정 방지와 완료 전 처리 조건은 유지합니다. AI 호출·자동 재전송·추가 조회 단계를 만들지 않습니다.

입력창과 저장소는 사용자가 쓴 앞뒤 공백·줄바꿈을 그대로 보존합니다. 빈 입력과 전송 확인 대기 중의 중복 본문 비교에만 공백 정리를 사용합니다. 새 요청의 같은 ID 재시도는 원문까지 일치해야 하며, 예전 요청은 저장된 본문과 기존 안내 형식을 유지합니다. 과거 기록을 다시 쓰지 않습니다.

격리된 가상 자료로 원문 보존, 프로젝트별 총괄 조회, 추가 요청 연결, 중복 전송 차단과 예전 저장 재시도의 불변성을 확인합니다. 레이아웃 변경은 없으며, 실제 Codex의 채팅 간 전달은 이 검사에서 실행하지 않습니다.

## 0.4.2 · 쉬운 본문과 펼쳐 보는 작업 상세

`room_post`·`room_reply`에 선택 항목 `details`를 추가합니다. 작성자는 원래 보고 턴에서 일반인이 이해할 수 있는 쉬운 `text`와 필요한 기술 상세를 함께 남깁니다. 본문에는 완성한 것·남은 문제·다음 할 일을, 상세에는 정확한 경로·검사 기록·설정·기술 근거를 둡니다. 실패·미검증·승인 필요와 보존·권한 조건은 쉬운 본문에서도 알립니다. 역할·전달·배정·검증 절차를 바꾸거나 정보를 삭제하지 않으며, 담당자의 조회에는 두 필드가 그대로 포함됩니다. 자연스러운 질문·답변 지침은 실제 협의에만 적용하고 가짜 대화나 추가 확인 호출을 만들지 않습니다.

UI는 상세를 기본적으로 접고 네이티브 details/summary로 펼칩니다. 펼치기·접기는 도구나 AI를 부르지 않으며 같은 프로젝트의 갱신 때 열림 상태를 유지합니다. 프로젝트 전환·닫힘·분리된 이전 요소의 늦은 이벤트는 다른 화면의 상태를 바꾸지 않습니다. 본문과 상세는 재시도에도 변경할 수 없고, 과거 본문만 있는 기록은 원문대로 유지합니다. 기존 기록을 자동 번역하거나 AI로 다시 요약하지 않습니다. 새 지침·도구 설명·작성 및 조회 글에는 정상 문맥 사용량이 있어 토큰 수가 기존과 정확히 같다고 보장하지 않습니다.

가상 담당자·가상 파일을 사용해 본문/상세의 전문 보존, 재시도 불변성, 질문 연결, 잘못된 입력 차단과 HTML 비실행을 검사합니다. Chromium 1280px·420px 하네스는 접기/펼치기·새로고침 유지·가로 넘침·고정 입력창·기존 표시 전환과 닫힘 동작을 확인하며 예시 이미지는 실제 프로젝트 기록이 아닙니다. 실제 Codex 표시 전환과 실제 담당자의 향후 말투 준수까지 이 하네스로 확인한 것은 아닙니다.

## 0.4.1 · 만든 담당자의 최종 이미지 첨부

이미지·화면·UI·디자인·3D 결과의 배정에 `requireFinalImage:true`를 지정하고, 해당 담당자 본인의 완료 보고에 유효한 최종 이미지가 없으면 완료 처리를 거절합니다. 중간 이미지나 총괄의 대리 첨부는 이를 대체하지 않습니다. 조건은 재시작·중단 복구·담당자 인계 뒤에도 보존하며, 이미 지정한 조건은 해제할 수 없습니다. 총괄은 만든 담당자의 완료 첨부를 통상 통합 과정에서 확인하고 이미지를 중복 게시하지 않습니다. 생성·캡처·파일 접근 차단은 성공으로 표시하지 않습니다.

가상 파일·담당자를 사용하는 저장소·MCP 검사로 누락 첨부 차단, 필수 조건 보존, 재시도 중복 방지, 차단 보고 및 복구를 확인합니다. 파일 첨부의 유효성 검사는 실제 완성 상태의 시각적 판정을 대신하지 않으며, 배정 조건을 지정하지 않은 과거 작업을 자동 수정하지 않습니다. 새 AI 호출·정기 알림·이미지 수집기를 추가하지 않습니다. 화면 코드는 버전 메타데이터만 갱신하며 레이아웃 변경은 없습니다. 실제 Codex 호스트에서 생성부터 게시까지의 전체 흐름은 별도 확인이 필요합니다.

## 0.4.0 · 작업 보호와 완료 사용량

파일·Editor 소유권, 검증 횟수, 체크포인트 복구, Unity CLI 실행과 사용량 가져오기를 로컬 모듈로 분리했습니다. 새 `room_work`, `room_validation`, `room_usage` 세 도구를 추가하며 정기 AI 호출·자동 재전송·자동 검증 재시도·새 채팅은 추가하지 않습니다. 화면은 작업 보호와 검증을 메뉴에, 완료된 작업의 담당자별 토큰·계정 한도 사용률을 최종 결과 아래와 메뉴에 표시합니다. 기록 누락은 0으로 계산하지 않고, 계정 한도를 담당자별로 임의 배분하지 않습니다.

검증은 가상 담당자·격리 폴더·가짜 Unity CLI 프로세스를 사용합니다. 독립 프로세스 간 소유권 충돌, stale 해시·경로 탈출, 중단 저장 복구, 재시도 차단, 누락 증거·빈 빌드 거부, 로컬 사용량 중복 방지와 한도 초기화의 처리를 확인합니다. Chromium 1280px·420px에서 완료 사용량 배치, 수평 넘침, 화면 높이 전환과 닫힌 뒤 지연 응답도 확인합니다. 스크린샷의 이름·토큰·한도 수치는 가상 테스트 자료입니다.

실제 Codex 표시 모드 전환과 실제 Unity 프로젝트의 Editor·라이선스·PlayMode·빌드는 이 격리 검증으로 확인한 것이 아닙니다. 네이티브 로그 형식과 한도 자료는 호스트에 따라 없거나 달라질 수 있습니다. 플러그인 밖의 파일 저장·명령은 전역 차단하지 않으며, 현재 사용자 데이터나 다른 프로젝트의 실행 환경을 검증 목적으로 변경하지 않습니다.

## 확인한 결함

기존 화면은 대화 영역의 높이를 `100dvh - 260px`로 계산했습니다. 내용 크기에 맞춰 iframe 높이를 바꾸는 호스트에서 이 높이를 다시 측정하면, 나머지 헤더·입력창·접힌 제어 영역의 실제 높이와 260px의 차이가 매번 누적됩니다. 전체 화면에서 inline으로 돌아올 때도 별도 처리가 없었습니다.

독립 Chromium 호스트 모형에서 이전 소스는 20번 재측정하는 동안 높이가 1,107px에서 3,140px로 매번 107px씩 증가했습니다. 이는 사용자가 보고한 흔들림의 가능한 원인을 실제 레이아웃으로 재현한 결과입니다. Codex 자체의 오버레이/스크롤 동작 전체를 재현했다는 뜻은 아닙니다.

또한 `ui/resource-teardown` 응답과 종료 정리가 없어 호스트의 닫힘 요청을 처리하지 못했습니다. 단순한 document visibility만으로는 종료 상태를 보장할 수 없었습니다.

## 수정

- Inline 기본 높이는 iframe viewport와 독립적인 720px이며 호스트의 명시적 높이 제한을 적용합니다. 전체 화면은 호스트의 고정 높이를 사용합니다.
- 헤더·대화·입력·하단 제어는 하나의 제한된 flex 영역 안에 배치합니다. 내용이 길면 내부에서 스크롤합니다.
- 호스트 context 변경을 병합하며 화면 모드만 바뀌면 이전 모드의 크기를 재사용하지 않습니다.
- Flexible 높이 알림은 실제 목표 높이가 바뀔 때만 보냅니다.
- 닫힘 요청에는 응답하고 타이머·대기 중 RPC를 정리합니다. pagehide도 같은 정리를 수행합니다. 늦게 도착한 상태와 이벤트는 종료된 화면을 되살리거나 새 작업을 보내지 못합니다.
- 호스트 요청 ID와 화면 요청 ID는 별개이므로, 종료 요청을 대기 중 응답 ID보다 먼저 구분합니다.

## 검증

2026-10-28 기준 32개 Node 검사가 통과했습니다. 여기에는 전체 화면/inline 전환, 종료 시 ID 충돌, 진행 중 조회 종료, 늦은 이벤트, pagehide 검사가 포함됩니다.

실제 Chromium 엔진의 격리된 호스트 모형에서 너비 1,280px와 420px 각각 20회 모드 전환 및 20회 높이 재측정을 수행했습니다. 수정본은 매번 720px로 유지됐고 입력창과 대화 영역이 겹치지 않았습니다. 종료 응답 후 4.2초 동안 추가 상태 조회나 모델 메시지가 없었습니다. 테스트 자료는 `.local/`에만 저장됩니다.

Codex 앱에서 사용자가 겪은 빠른 상하 움직임이 완전히 사라졌는지는 새 플러그인을 로드한 뒤 실제 닫기/축소 동작으로 확인해야 합니다. 이 문서의 브라우저 검사를 실제 Codex 검증으로 표시하지 않습니다.

## 0.3.2 · 하단 공간 확보

팀과 회의 제어, 요청 처리 기록, 전송 안내를 상단 메뉴 버튼의 modal dialog로 옮겼습니다. 평상시 하단에는 입력창만 남으며 메뉴를 열어도 대화 영역의 높이나 입력창 위치는 바뀌지 않습니다. 닫기 버튼·Escape·바깥쪽 클릭으로 닫을 수 있고 키보드 포커스는 메뉴 버튼으로 돌아갑니다. 기존 프로젝트 연결과 전송/조회 정책은 그대로 유지합니다.

## 0.3.3 · Enter 전송 중심 입력창

큰 전송 버튼을 화면과 탭 순서에서 제거했습니다. 내부 submit 요소와 기존 전송 가능 여부 검사는 유지하여 Enter 전송, Shift+Enter 줄바꿈, 한국어 IME, 빈 입력·일시정지·중복·실패 후 불확실 상태의 보호 동작을 보존합니다. 입력창에는 작은 키보드 안내를 연결했습니다. 상단 회의실 메뉴와 프로젝트 연결·실제 대화 데이터는 변경하지 않습니다. 실제 Codex 화면 검증은 별도이며 독립 브라우저 결과와 구분합니다.

## 0.3.7 · 작업 중 추가 메시지

기존에는 저장부터 `ui/message` 응답까지 하나의 전송 잠금을 유지했고, 15초 응답 지연이나 실패가 회의실 전체의 새 전송을 막았습니다. 이제 저장 중에만 짧게 잠그며, 각 메시지의 전송 확인 대기·확인 필요·거절·호스트 전달 확인을 별도로 표시합니다. 지연된 응답은 계속 수신하되 새 초안이나 다른 프로젝트의 입력을 지우지 않습니다. 확인 대기·불확실 상태의 동일 본문은 중복 전송하지 않으며, 다른 추가 내용은 계속 보낼 수 있습니다. 자동 재전송은 추가하지 않습니다.

추가 메시지는 별도 요청 ID와 `followUpTo`로 가장 최근의 활성 원래 요청에 연결됩니다. `room_get`은 연결된 추가 요청을 반환하고, 총괄은 중간 판단 및 완료 전에 확인해 현재 작업에 반영합니다. 원래 담당자의 전달 예약을 초기화하거나 이미 진행 중인 작업을 새로 시작하지 않습니다. 미처리 추가 요청은 총괄의 원래 최종 답변 저장만 막습니다. 추가 메시지의 전달이나 구현·수정 작업은 막지 않습니다. 실패한 추가 요청도 성공한 것으로 무시할 수 없습니다. 이미 완료된 원래 요청에는 새 연결을 저장하지 않고, 초안을 유지한 채 새 요청으로 보내도록 안내합니다.

[OpenAI MCP Extensions 규격](https://github.com/openai/mcp-extensions/blob/main/docs/spec.md#uimessage-extensions)의 `target: active, send: true`로 각 사용자 전송을 한 번 전달합니다. 이 규격은 실행 중인 턴을 강제로 중단하는 필드를 정의하지 않습니다. [호스트의 후속 메시지 설정](https://learn.chatgpt.com/docs/app/settings)에 따라 활성 작업 조정 또는 다음 턴 대기가 적용될 수 있으며, 긴 도구 실행 도중 즉시 수정 반영을 보장하지 않습니다. 별도 모델 실행 환경이나 유휴 AI 호출은 추가하지 않았습니다.

40개 Node 검사에서 진행 중 추가 요청 연결, 완료 누락 방지, 프로젝트 격리, 중복 방지, 지연·역순 응답, 닫힘 후 늦은 전달 차단을 확인했습니다. 너비 1,280px와 420px의 독립 Chromium 모형에서는 첫 전송 응답을 보류한 상태에서 두 번째 전송과 초안 보존, 기존 높이·키보드·종료 처리가 통과했습니다. 실제 Codex의 실행 중 메시지 도착 시점과 native 화면 전환은 미검증입니다.

## 0.3.8 · 답변과 안내 가독성

본문은 넓은 화면에서 15px, 좁은 화면에서 14px로 표시하고 줄 높이를 글자 크기의 1.9배로 늘렸습니다. 단어 사이 간격, 문단 여백과 발언 간 간격을 조정하고, 안내 글씨도 키웠습니다. 안내 메뉴는 전달 대상, 작업 중 추가 전달, 전송 상태, 사용량, 일시정지로 나누었습니다.

답변의 Markdown 제목·굵은 글씨·목록·인라인 코드·코드 블록을 안전한 DOM 요소로 표시합니다. 원문 데이터와 공백·줄바꿈을 보존하며 HTML은 실행하지 않고 글자로 표시합니다. 코드 블록은 내부에서 가로로 스크롤하고, 과도하게 중첩된 목록은 깊이를 제한하면서 원문을 보존합니다. 운영 스킬에는 자연스러운 한국어 띄어쓰기와 짧은 문단 작성 기준을 추가했습니다. 과거 기록을 다시 쓰거나 별도 AI 호출을 추가하지 않습니다.

관련 Node 검사 18개와 너비 1,280px·420px의 독립 Chromium 검사가 통과했습니다. 예시 답변의 문단·목록·코드, 글자 간격, 페이지 너비, 기존 전송·높이·종료 처리를 확인했습니다. 실제 Codex의 native 화면 전환은 별도 미검증입니다.

## 0.3.9 · 빈 줄 없는 긴 글과 쉬운 보고

160자 이상의 일반 본문은 문장 경계와 기존 줄바꿈을 이용해 표시상 덩어리를 나눕니다. 원문 글자와 순서는 유지하며 저장 내용과 모델에 전달하는 내용은 바꾸지 않습니다. 인라인 코드·강조·URL 내부와 코드 블록은 자동 나누기에서 제외합니다. 본문 폭을 줄이고 문단·목록 여백과 발언 구분선을 보강했습니다. 문장 경계가 없는 긴 한 문장은 임의로 자르지 않습니다.

새 보고에는 쉬운 표현, 문단당 1–2문장, 항목별 줄바꿈을 사용하도록 지침을 보강했습니다. 보고 길이는 작업 범위나 검증 깊이를 제한하지 않으며 판단에 필요한 근거·제약·위험·미해결 문제는 보존합니다. 과거 기록의 재작성이나 가독성 개선용 AI 호출은 추가하지 않습니다.

Node 검사 44개와 너비 1,280px·420px의 독립 Chromium 모형에서 원문 보존, 문단 여백, 넘침 방지, 기존 전송·닫힘 동작을 확인했습니다. 개발자 자체 검증이며 별도 QA 담당 검증 및 실제 Codex display-mode 전환은 미검증입니다.

사용량 확인: 줄바꿈·여백은 로컬 DOM/CSS 처리입니다. UI 읽기·갱신과 표시 나누기는 모델을 호출하지 않습니다. 실제 참여자의 작업·보고와 활성 모델 턴의 도구 호출·기록 조회에는 정상 사용량이 발생합니다. [공식 OpenAI 안내](https://learn.chatgpt.com/docs/pricing)에 따르면 입력·응답·도구 결과 등의 토큰과 모델·추론·문맥·캐시가 사용량에 영향을 줍니다. 빈 줄의 정확한 증감이나 절감률은 측정하지 않았습니다.

## 0.3.10 · 입력창 아래 기록을 메뉴로 이동

보낸 글 미리보기·요청 ID·전송 확인 내역, 연결 상태와 키보드 안내를 메뉴의 ‘전송 상태와 입력 안내’로 옮겼습니다. 입력 대상 라벨은 접근성 이름으로 유지하되 화면 공간을 차지하지 않습니다. 평소 하단에는 입력창만 남습니다. 확인이 필요한 전송이나 거절이 있으면 메뉴 버튼에 ‘전송 확인 필요’를 표시하며 자동 재전송은 하지 않습니다. 오류·일시정지 안내와 기존 전송 보호 동작은 유지합니다.

Node 검사 44개 및 1,280px·420px Chromium 모형 검사를 통과했습니다. 두 번의 전송과 지연된 응답 후에도 입력창의 위쪽 위치가 그대로이며, 전송 내역은 메뉴를 열면 확인됩니다. 메뉴의 Escape·닫기와 포커스 복귀도 유지됩니다. 개발자 자체 검증이며 별도 QA 및 실제 Codex display-mode 전환은 미검증입니다. 합성 예시 화면과 로그는 `.local/`에만 저장합니다.

## 0.3.11 · 작업 중 시안과 이미지 첨부

`room_post`와 `room_reply`에 선택 인수 images를 추가했습니다. 진행 보고에 시안·스크린샷을 게시해 완료 전에도 회의실에서 확인할 수 있습니다. 한 발언에 최대 4개, 파일당 8 MiB의 로컬 PNG/JPEG/GIF/WebP를 지원합니다. 서버가 명시적으로 지정한 파일만 읽고 내용 해시로 식별한 사본을 외부 런타임 데이터 폴더에 보관합니다. 경로나 파일을 임의로 열 수 있는 UI 도구는 추가하지 않았습니다. 이미지 조회는 프로젝트·요청·발언·이미지 ID가 모두 일치해야 합니다.

저장 시 입력 파일 목록의 해시를 비교하므로 동일 발언 키/최종 답변의 재시도는 파일 변경·삭제 후에도 원래 사본을 유지합니다. 첨부 변경이나 제거로 원문을 덮어쓸 수 없고, 새 시안은 새 진행 발언으로 남깁니다. 기존 텍스트 기록은 그대로 열립니다. 정해진 크기 이내의 실제 래스터 형식만 허용하고 파일 읽기 오류·잘못된 혼합 배치는 발언 저장 전에 거절합니다. SVG·HTML과 원격 URL·상대 경로는 받지 않습니다.

UI 전용 `room_image`는 이미지 데이터를 tool result `_meta`로만 반환합니다. 모델에게 보이는 content/structuredContent와 주기적 room_state에는 바이트와 원본 경로가 없습니다. 본문 이미지는 보이는 위치에 가까워질 때 최대 2개씩 로드하고 캐시를 제한합니다. 미리보기 영역 높이를 미리 확보하여 이미지 로드가 입력창을 밀지 않게 했습니다. 클릭으로 확대하고 Escape/닫기로 닫습니다. 실패는 재시도 버튼으로 표시하며 자동 재시도하지 않습니다. 프로젝트 전환·새 렌더·종료 뒤 늦은 응답은 이전 화면을 변경하지 않고 닫힌 뒤 대기열에서 새 호출을 시작하지 않습니다.

합성 파일을 사용한 Node 검사 50개와 1,280px·420px 독립 Chromium 모형 검사를 통과했습니다. 이미지 디코딩·확대·포커스 복귀·캐시·넓이·기존 키보드 전송·종료 뒤 지연 응답을 확인했습니다. 검증 화면은 `.local/image-progress-*.png`, `.local/image-zoom-*.png`, 로그는 `.local/image-tests.log`와 `.local/image-layout-run.log`입니다. 개발자 자체 점검이며 별도 QA는 연결되지 않아 수행하지 않았습니다. 실제 Codex의 이미지 `_meta` 전달·CSP·native display-mode 전환은 미검증입니다. 다른 채팅의 이미지 자동 미러링, 주기적 캡처나 추가 AI 호출은 추가하지 않았습니다.

## 0.3.12 · 필요한 때만 이미지 보고

사용자의 빈도 선호를 운영 스킬에 반영했습니다. 요청받은 경우, 시각적 선택에 대한 판단이 필요한 경우, 글만으로 전달하기 어려운 오류·중요한 화면 변경의 증거가 필요한 경우에만 이미지를 게시합니다. 기존 대표 이미지 1장을 우선하며 비교가 꼭 필요할 때만 추가합니다. 단계별 의무 보고, 동일·유사 화면 반복, 보고용 추가 생성·캡처와 최종 보고의 중복 첨부를 피합니다. 필요한 구현·QA 검증 및 로컬 증거 보관은 유지합니다. 지침과 버전 표시만 변경하여 형식·JSON 검사를 수행했고 이미 통과한 실행 검사는 반복하지 않았습니다.

## 0.3.13 · 완료 보고에는 최종 이미지

사용자 요청에 따라 시각적 결과물이 있는 작업은 완료 보고에 실제 최종 상태의 대표 이미지 1장을 포함합니다. 중간 이미지의 게시 여부와 관계없이 완료 결과를 확인할 수 있도록 했습니다. 최종 상태를 정확히 보여 주는 기존 이미지는 재사용하고 필요하면 허용된 범위에서 최종 화면을 한 번 캡처합니다. 캡처·파일 접근 불가 시에는 한계를 알리며 비시각적 작업의 장식 이미지는 만들지 않습니다. 중간 보고는 필요한 경우에만 하는 기존 기준을 유지합니다. 지침·문서·버전 표시만 변경하여 형식·JSON 검사와 설치본 일치 여부를 확인하며 실행 검사는 반복하지 않습니다.

## 0.3.14 · 협업 지침 전체를 공통 패키지에 포함

총괄 운영 12개 항목, 프로그래머 병렬 협업 9개 절과 QA 오류 대응 8개 규칙의 전문을 패키지 내부 references/collaboration-policy.md에 보관했습니다. 역할·소통·스킬 선택·파일 보존·공유 앱 조작권·QA 인계·모델 선택 제한·이벤트 대기·보고·종료 기준도 함께 공통화했습니다. SKILL.md에 모든 프로젝트에서 적용할 핵심 요약과 최초 협업 시 전문 확인 절차를 연결했습니다. 실제 개인 이름·대화 ID·연결 명단·원본 로컬 경로는 옮기지 않았습니다.

프로젝트별 사용자의 역할 지정·승인 범위와 실제 호스트/도구 제한을 우선합니다. 두 명 이상인 기존 프로그래머의 독립 병렬 업무를 우선하되 없는 역할을 만들거나 다른 프로젝트의 팀을 재사용하지 않습니다. 모델 선택은 허용된 다음 배정에만 적용하고, 도구가 지원하지 않으면 현재 설정과 한계를 유지합니다. 새 대화·외부 메시지·자동 모델 변경·주기적 AI 호출은 추가하지 않았습니다. 전문은 세션 최초에 확인하고 후속에는 관련 부분과 변경분만 전달합니다.

## 0.3.16 · 공용 보고를 쉬운 말로 작성

QA 등 사용자가 읽는 공용 보고는 원래 작성 턴에 쉬운 말로 결과·통과 범위·남은 문제·차단·미검증과 다음 조치를 먼저 쓰도록 지침을 보강했습니다. 기술 식별자·코드 위치·원문 로그·수치는 상세 검증 기록과 필요한 인계에 유지합니다. 앞선 검사 중단을 아직 검증하지 않은 목표 기능의 실패로 오인하지 않게 하고, 좁은 화면 검사·최종 캡처에 도달하지 못한 사실도 보존합니다.
